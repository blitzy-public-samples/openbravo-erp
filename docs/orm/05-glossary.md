## Terms

### Access level

The access level is the code of an AD table that `Entity#initialize(Table)` maps to an `AccessLevel` value and an `AccessLevelChecker` (boundary) of the same name: `1` is `ORGANIZATION`, `3` is `CLIENT_ORGANIZATION`, `4` is `SYSTEM`, `6` is `SYSTEM_CLIENT` and `7` is `ALL`, and any other code fails with `Check.fail` (`Entity#initialize(Table)`). `Entity#checkAccessLevel(String, String)` passes the entity name and the ids of a [client](#client) and an [organization](#organization) to that checker, and its Javadoc states that it throws `OBSecurityException` when they are not valid for the access level (`Entity#checkAccessLevel`). `SecurityChecker#checkWriteAccess(Object)` delegates to the private `SecurityChecker#checkWriteAccess(Object, boolean)`, which calls `Entity#checkAccessLevel(String, String)` as its last statement in every mode, [admin mode](#admin-mode) included, and whose source comment says that the access-level check must also be done for administrators (`SecurityChecker#checkWriteAccess(Object)`, `SecurityChecker#checkWriteAccess(Object, boolean)`).

Used in: [02-runtime-model](./02-runtime-model.md#access-level), [04-security-and-filtering](./04-security-and-filtering.md#reading-guide)

### Access strategy

The access strategy is the class that the `access` attribute of a generated mapping element names: `DalMappingGenerator#getAccessorAttribute` returns that attribute with the class name of `DalPropertyAccessStrategy` (boundary), and the generator appends it to the `<id>`, `<composite-id>`, `<property>`, [many-to-one](#many-to-one), [one-to-one](#one-to-one) and [bag](#bag) elements built by the methods cited here (`DalMappingGenerator#getAccessorAttribute`, `DalMappingGenerator#generateStandardID`, `DalMappingGenerator#generateCompositeID`, `DalMappingGenerator#generatePrimitiveMapping`, `DalMappingGenerator#generateReferenceMapping`, `DalMappingGenerator#generateOneToMany`). The `_computedColumns` many-to-one and the client and organization many-to-ones of the computed-column class mapping write the same class name, `org.openbravo.dal.core.DalPropertyAccessStrategy`, directly into their `access` attribute (`DalMappingGenerator#generateComputedColumnsMapping`, `DalMappingGenerator#generateComputedColumnsClassMapping`). `DalPropertyAccessStrategy` is a boundary class, and this documentation states nothing about how it reads or writes property values (`DalMappingGenerator#getAccessorAttribute`).

Used in: [01-architecture](./01-architecture.md#which-entities-are-mapped)

### Active filter

The active filter is the Hibernate session filter `activeFilter`, which `DalMappingGenerator#generateMapping(Entity)` declares with the condition `:activeParam = isActive` in the mapping of every [active-enabled entity](#active-enabled-entity), and which `DalMappingGenerator#generateOneToMany` attaches to every [bag](#bag) whose target entity is active-enabled (`DalMappingGenerator#generateMapping(Entity)`, `DalMappingGenerator#generateOneToMany`). `OBDal#enableActiveFilter()` enables it on the [session](#session) of the instance's [pool](#pool) with `activeParam` set to `Y`, `OBDal#disableActiveFilter()` disables it, and `OBDal#isActiveFilterEnabled()` reports whether it is enabled (`OBDal#enableActiveFilter()`). It is separate from the active restriction that `OBCriteria` and `OBQuery` add under their own `setFilterOnActive(boolean)` switch, which defaults to true and does not read the session filter (`OBCriteria#initialize`, `OBQuery#addOrgClientActiveFilter`). The Javadoc of `OBDal#enableActiveFilter()` says the method overrides those switches, and [04-security-and-filtering.md, The session active filter](./04-security-and-filtering.md#the-session-active-filter) records this as an ambiguity that it does not resolve (`OBDal#enableActiveFilter()`).

Used in: [01-architecture](./01-architecture.md#per-entity-rules), [03-dal-service-api](./03-dal-service-api.md#obdalenableactivefilter), [04-security-and-filtering](./04-security-and-filtering.md#reading-guide)

### Active organization

An active organization is an [organization](#organization) whose record is active: when no organization id is passed, `OBContext#initialize(String, String, String, String, String, String)` takes the default organization of the user only when it is active, and otherwise, for a [role](#role) that is not an [automatic role](#automatic-role), the organization of the first active [role-organization assignment](#role-organization-assignment) whose organization is active (`OBContext#initialize(String, String, String, String, String, String)`). The active organizations of a role are the organizations of its active role-organization assignments whose organization is active, plus, for an automatic role, the organizations that `RoleAccessUtils` (boundary) returns, plus the organizations added through `OBContext#addWritableOrganization(String)`; the private `OBContext#getOrganizationList(Role, List, Set, boolean)` builds that list without duplicates (`OBContext#getOrganizationList(Role, List, Set, boolean)`). `OBContext#setWritableOrganizations(Role)` adds them to the [writable organizations](#writable-organizations), and `OBContext#setReadableOrganizations(Role)` makes the [readable organizations](#readable-organizations) the union of their [natural trees](#natural-tree), or every organization of the current client when they include `"0"` (`OBContext#setWritableOrganizations(Role)`, `OBContext#setReadableOrganizations(Role)`). Once that `"0"` branch has run, the list of active organizations that `OBContext#getOrganizationList(Role, List, Set, boolean)` returns is the client-wide list cached by `OBContext#getOrganizations(Client)`, until `OBContext#addWritableOrganization(String)` clears it; [04-security-and-filtering.md, Readable and writable sets](./04-security-and-filtering.md#readable-and-writable-sets) records this as an ambiguity that it does not resolve (`OBContext#getOrganizationList(Role, List, Set, boolean)`).

Used in: [04-security-and-filtering](./04-security-and-filtering.md#initialization-order)

### Active-enabled entity

An active-enabled entity is an [entity](#entity) with a primitive property named `active`: `Property#initializeName` matches that name case-insensitively, sets the entity's active-enabled flag and marks the property as the active column, and `Entity#isActiveEnabled` returns the flag, which its Javadoc describes as the entity having an isActive property (`Property#initializeName`, `Entity#isActiveEnabled`). `DalMappingGenerator#generateMapping(Entity)` declares the [active filter](#active-filter) in the [Hibernate mapping](#hibernate-mapping) of every active-enabled entity, and `DalMappingGenerator#generateOneToMany` attaches it to every [bag](#bag) whose target entity is active-enabled (`DalMappingGenerator#generateMapping(Entity)`, `DalMappingGenerator#generateOneToMany`). While the `setFilterOnActive(boolean)` switch is on, `OBCriteria#initialize` restricts `active` to true for an active-enabled entity, and `OBQuery#addOrgClientActiveFilter` appends `active='Y'` (`OBCriteria#initialize`, `OBQuery#addOrgClientActiveFilter`). `Entity#getImplementsStatement` adds `ActiveEnabled` (boundary) to the interfaces of the entity's [generated class](#generated-class), while the query classes read `Entity#isActiveEnabled` instead of testing for that interface (`Entity#getImplementsStatement`, `OBCriteria#initialize`).

Used in: [01-architecture](./01-architecture.md#per-entity-rules), [02-runtime-model](./02-runtime-model.md#flags), [04-security-and-filtering](./04-security-and-filtering.md#client-organization-and-active-filtering)

### Admin context

The admin context is a single `OBContext` for user, [role](#role), [client](#client) and [organization](#organization) `"0"`, shared by every thread: `OBContext#setAdminMode(boolean)` pushes an entry onto the [admin mode stack](#admin-mode-stack) and, when the thread has no context, installs the admin context in the thread, creating it on first use and reusing it afterwards (`OBContext#setAdminMode(boolean)`). When the context of the thread already is the admin context, `OBContext#setAdminMode(boolean)` returns at that point (`OBContext#setAdminMode(boolean)`). `OBContext#restorePreviousMode()` removes the admin context from the thread when the admin mode stack is empty after its pop (`OBContext#restorePreviousMode()`). `OBContext#setOBContextInSession(HttpServletRequest, OBContext)` refuses to store it in the [HTTP session](#http-session) and logs a warning that the context has not been reset correctly and that the admin context should always be removed in a `finally` block (`OBContext#setOBContextInSession(HttpServletRequest, OBContext)`).

Used in: [04-security-and-filtering](./04-security-and-filtering.md#creating-and-installing-a-context)

### Admin mode

Admin mode is the state in which `OBContext#isInAdministratorMode()` is true: the top of the thread's [admin mode stack](#admin-mode-stack) is an admin entry pushed by `OBContext#setAdminMode(boolean)`, the deprecated flag of `OBContext#setInAdministratorMode(boolean)` is set, or the [role](#role) is `"0"` (`OBContext#isInAdministratorMode()`). In admin mode the [entity access](#entity-access) read and write checks are skipped, and `OBDal#save(Object)` calls neither `EntityAccessChecker#checkWritable(Entity)` nor `SecurityChecker#checkWriteAccess(Object)`, while the [access level](#access-level) check still runs, because `SecurityChecker#checkWriteAccess(Object, boolean)` calls it outside its admin-mode condition and `OBInterceptor#doEvent` calls `SecurityChecker#checkWriteAccess(Object)` in every mode (`EntityAccessChecker#checkReadable`, `EntityAccessChecker#isWritable`, `OBDal#save(Object)`, `SecurityChecker#checkWriteAccess(Object, boolean)`, `OBInterceptor#doEvent`). The client, organization and active restrictions of `OBCriteria` and `OBQuery` are added in admin mode too, because only their read check depends on `OBContext#isInAdministratorMode()` (`OBCriteria#initialize`, `OBQuery#createQueryString`, `OBQuery#addOrgClientActiveFilter`). The Javadoc of `OBContext#setAdminMode(boolean)` says that it lets the current user run with Administrator privileges and that `OBContext#restorePreviousMode()` restores the previous privileges; the first pushes an admin entry onto the admin mode stack, and the second pops the top entry or, when the stack is empty, logs an unbalanced-call warning (`OBContext#setAdminMode(boolean)`, `OBContext#restorePreviousMode()`). `OBContext#setAdminMode()` calls `OBContext#setAdminMode(boolean)` with `false`, which switches the [org/client access check](#orgclient-access-check) off, although its Javadoc says entity access will also be checked; 04 records this as an ambiguity (`OBContext#setAdminMode()`). The matrix of what each mode skips is in [04-security-and-filtering.md, What admin mode skips](./04-security-and-filtering.md#what-admin-mode-skips) (`OBContext#doOrgClientAccessCheck()`).

Used in: [01-architecture](./01-architecture.md#layers), [02-runtime-model](./02-runtime-model.md#values-identity-and-the-new-object-flag), [03-dal-service-api](./03-dal-service-api.md#obdalsaveobject), [04-security-and-filtering](./04-security-and-filtering.md#reading-guide)

### Admin mode stack

The admin mode stack is the per-thread stack of `OBAdminMode` (boundary) entries onto which `OBContext#setAdminMode(boolean)` pushes an entry marked as admin mode and carrying the passed org/client flag, and from which `OBContext#restorePreviousMode()` pops, logging an unbalanced-call warning when the stack is empty (`OBContext#setAdminMode(boolean)`, `OBContext#restorePreviousMode()`). A separate stack holds the entries of [cross-org reference admin mode](#cross-org-reference-admin-mode), which `OBContext#setCrossOrgReferenceAdminMode()` pushes and `OBContext#restorePreviousCrossOrgReferenceMode()` pops (`OBContext#setCrossOrgReferenceAdminMode()`). When the admin stack is empty after a pop and the thread holds the shared [admin context](#admin-context), `OBContext#restorePreviousMode()` removes that context from the thread (`OBContext#restorePreviousMode()`). `OBContext#clearAdminModeStack()` logs the unbalanced-call warning for each non-empty stack and clears both, and `DalRequestFilter#doFilter` calls it at the end of each request (`OBContext#clearAdminModeStack()`, `DalRequestFilter#doFilter`). `OBContext#initialize(String, String, String, String, String, String)` pushes a temporary admin entry directly onto the stack while it resolves a context, and pops it in a `finally` block (`OBContext#initialize(String, String, String, String, String, String)`).

Used in: [01-architecture](./01-architecture.md#request-lifecycle), [04-security-and-filtering](./04-security-and-filtering.md#initialization-order)

### Alias

An alias is a name by which a query refers to the object it queries: `OBDal#createCriteria(Class, String)` and `OBDal#createCriteria(String, String)` pass their `alias` argument to `OBCriteria#OBCriteria(String, String, SessionImplementor)`, and the Javadoc of `OBDal#createCriteria(Class, String)` describes it as an alias that can be used to refer to the specified object (`OBDal#createCriteria(Class, String)`, `OBDal#createCriteria(String, String)`). In the clause given to `OBQuery`, `OBQuery#createQueryString` reads a leading `as` and the word after it, without a trailing comma, as the alias; it then starts the query string with `select` and the alias unless a [select clause](#select-clause) is set, and passes the alias with a dot to `OBQuery#addOrgClientActiveFilter`, which prefixes every restriction it appends with it (`OBQuery#createQueryString`, `OBQuery#addOrgClientActiveFilter`). `OBCriteria#initialize` creates an alias of its own for the path of each dotted order-by entry, as [join](#join) describes (`OBCriteria#initialize`).

Used in: [03-dal-service-api](./03-dal-service-api.md#obdalcreatecriteriaclass-string), [04-security-and-filtering](./04-security-and-filtering.md#query-restrictions)

### Application Dictionary (AD)

The Application Dictionary is the set of AD records from which `ModelProvider#initialize` builds the [runtime model](#runtime-model): through the [model session factory](#model-session-factory) it reads all `Table` records sorted by name, all `Reference` records, all `Column` records, the `RefTable`, `RefSearch` and `RefList` records and the active `Module` records, and it creates one [entity](#entity) per remaining table (`ModelProvider#initialize`). `ModelProvider#initialize` applies no module filter, so a table that a module adds to the AD reaches the runtime model by the same path as a core table (`ModelProvider#initialize`, `ModelProvider#removeInvalidTables`). The AD model classes are boundary names, and this documentation does not describe AD tables, their columns or the database schema (`ModelSessionFactoryController#mapModel`).

- Code qualification: besides tables and columns, the model session factory maps the AD classes for references, reference lists, reference searches, reference tables, modules and packages (`ModelSessionFactoryController#mapModel`). `ModelProvider#initializeReferenceClasses` also registers with it the classes that reference [domain types](#domain-type) supply through their `getClasses()` (`ModelProvider#initializeReferenceClasses`). Unique constraints and column not-null flags come from database metadata, not from the AD (`ModelProvider#buildUniqueConstraints`, `ModelProvider#getColumnMandatories`). Some runtime properties, the one-to-many [child properties](#child-property) on parent entities, come from no AD column: `ModelProvider#createChildProperty` creates them (`ModelProvider#createChildProperty`).

Used in: [01-architecture](./01-architecture.md#reading-guide), [02-runtime-model](./02-runtime-model.md#reading-guide)

### Audit properties

The audit properties are the four properties `creationDate`, `createdBy`, `updated` and `updatedBy`: `Property#initializeName` marks a primitive `Date` property named `creationDate` or `updated`, and a reference property named `createdBy` or `updatedBy`, as audit info, comparing names case-insensitively; it sets the exact casing `creationDate`, `createdBy` and `updatedBy` on the matching properties, while the `updated` branch only marks audit info and leaves the name unchanged (`Property#initializeName`). `Entity#isTraceable` is true when exactly four properties of an entity are audit properties, and such an entity's generated class implements `Traceable` (`Entity#isTraceable`, `Entity#getImplementsStatement`). For a `Traceable` object, `OBInterceptor#doEvent` calls `OBInterceptor#onNew` when any audit property is null and `OBInterceptor#onUpdate` otherwise (`OBInterceptor#doEvent`). `OBInterceptor#onNew` sets each null audit property, the dates to the current date and the users to a [proxy](#proxy) of the context user, and `OBInterceptor#onUpdate` sets the updated date and the updated-by user (`OBInterceptor#onNew`, `OBInterceptor#onUpdate`). While `OBInterceptor#setPreventUpdateInfoChange(boolean)` is true in admin mode, `OBInterceptor#onUpdate` leaves `updated` and `updatedBy` unchanged (`OBInterceptor#onUpdate`).

Used in: [01-architecture](./01-architecture.md#request-lifecycle), [02-runtime-model](./02-runtime-model.md#how-the-runtime-model-is-built), [04-security-and-filtering](./04-security-and-filtering.md#interceptor-behavior)

### Automatic role

An automatic role is a [role](#role) that `RoleAccessUtils` (boundary) recognises as automatic and for which `OBContext` takes organizations from `RoleAccessUtils`; this documentation does not describe how that class decides or which organizations it returns (`OBContext#initialize(String, String, String, String, String, String)`, `OBContext#getOrganizationList(Role, List, Set, boolean)`). When no organization id is passed and the user has no active default organization, `OBContext#initialize(String, String, String, String, String, String)` takes, for an automatic role, the highest id among the organizations that `RoleAccessUtils` returns for the role instead of the organization of a [role-organization assignment](#role-organization-assignment), and takes the client of the role when no client id was passed (`OBContext#initialize(String, String, String, String, String, String)`). The organizations that `RoleAccessUtils` returns for an automatic role are added both to the [active organizations](#active-organization) of the role and to its [deactivated organizations](#deactivated-organization) (`OBContext#getOrganizationList(Role, List, Set, boolean)`, `OBContext#getDeactivatedOrganizations()`).

Used in: [04-security-and-filtering](./04-security-and-filtering.md#initialization-order)

### Bag

A bag is the Hibernate collection mapping that `DalMappingGenerator#generateOneToMany` emits for every [one-to-many property](#one-to-many-property): an inverse bag (`inverse="true"`) keyed on the column of the referenced property, with `not-null="true"` on the key when that property is mandatory, and ordered by the [order-by properties](#order-by-property) of the target entity (`DalMappingGenerator#generateOneToMany`). The bag of a [child property](#child-property) gets `cascade="all,delete-orphan"`, a bag whose owning or target entity is a [view entity](#view-entity) is `mutable="false"` and has no [cascade](#cascade), and a bag whose target entity is active-enabled carries the [active filter](#active-filter) (`DalMappingGenerator#generateOneToMany`).

Used in: [01-architecture](./01-architecture.md#per-entity-rules)

### Business object

A business object is an instance of a subclass of `BaseOBObject`, the abstract class that its Javadoc calls the root of the inheritance tree of all business objects; a concrete subclass has to provide an implementation of the abstract `BaseOBObject#getEntityName`, either its own or an inherited one, and `BaseOBObject#getEntity` resolves the object's [entity](#entity) once through `ModelProvider#getEntity(String)` (`BaseOBObject#getEntityName`, `BaseOBObject#getEntity`). Its values are kept in one array indexed by `Property#getIndexInEntity`, and code reads and writes them through the [dynamic API](#dynamic-api) or the [typed API](#typed-api) of its [generated class](#generated-class) (`BaseOBObject#getValue`, `BaseOBObject#get(String)`). `BaseOBObject` implements `BaseOBObjectDef`, `Identifiable`, `DynamicEnabled`, `OBNotSingleton` and `java.io.Serializable` (`BaseOBObject#get(String)`, `BaseOBObject#getEntity`). `OBDal` reads business objects with `OBDal#get(Class, Object)` and `OBDal#get(String, Object)`, saves them with `OBDal#save(Object)` and removes them with `OBDal#remove(Object)`, in the session of the instance's [pool](#pool) (`OBDal#get(Class, Object)`, `OBDal#get(String, Object)`, `OBDal#save(Object)`, `OBDal#remove(Object)`).

- Code qualification: when the class named by `Entity#getClassName()` cannot be loaded, `Entity#getMappingClass()` returns null, and its Javadoc states that the system then uses a [DynamicOBObject](#dynamicobobject) as the runtime class (`Entity#getMappingClass()`). The code establishes nothing further about `DynamicOBObject`, which is a boundary class, so no type hierarchy is stated for it (`Entity#getMappingClass()`).

Used in: [01-architecture](./01-architecture.md#layers), [02-runtime-model](./02-runtime-model.md#baseobobject-and-its-interfaces), [03-dal-service-api](./03-dal-service-api.md#reading-guide), [04-security-and-filtering](./04-security-and-filtering.md#cross-organization-reference-check)

### Cascade

Cascade is the Hibernate mapping attribute that the generated mapping sets on parent references and on bags: `DalMappingGenerator#generateReferenceMapping` adds `cascade="persist"` to every mandatory parent reference, and `DalMappingGenerator#generateOneToMany` adds `cascade="all,delete-orphan"` to the [bag](#bag) of a [child property](#child-property) and omits cascade when the owning or the target entity is a [view entity](#view-entity) (`DalMappingGenerator#generateReferenceMapping`, `DalMappingGenerator#generateOneToMany`). The source comment in `DalMappingGenerator#generateReferenceMapping` gives the reason for `persist`: it prevents cascade errors in which the parent would be saved after the child (`DalMappingGenerator#generateReferenceMapping`).

Used in: [01-architecture](./01-architecture.md#per-entity-rules)

### Child property

A child property is a [one-to-many property](#one-to-many-property) that `ModelProvider#createChildProperty` adds to a parent entity for a property of a child entity that references it: the new property uses `OneToManyDomainType`, targets the child entity, references that property of the child entity and is not mandatory (`ModelProvider#createChildProperty`). It comes from no AD column, and `ModelProvider#createPropertyInParentEntity` creates one for each property of an entity that is neither a [datasource-based entity](#datasource-based-entity) nor an [HQL-based entity](#hql-based-entity) and that `ModelProvider#shouldGenerateChildPropertyInParent` accepts (`ModelProvider#createPropertyInParentEntity`, `ModelProvider#initialize`). That method accepts a property flagged as child property in parent, or any eligible property when the `hb.generate.all.parent.child.properties` setting is true (`ModelProvider#shouldGenerateChildPropertyInParent`). The new property is also marked as a child, the flag that `Property#isChild` reads, only when that property of the child entity is a [parent link](#parent-link), and `DalMappingGenerator#generateOneToMany` gives a one-to-many property marked as a child `cascade="all,delete-orphan"` (`ModelProvider#createChildProperty`, `DalMappingGenerator#generateOneToMany`).

Used in: [01-architecture](./01-architecture.md#per-entity-rules), [02-runtime-model](./02-runtime-model.md#how-the-runtime-model-is-built)

### Child tree

The child tree of an organization is the set of organization ids that `OrganizationStructureProvider#getNaturalTree(String)` obtains by calling the provider's `getChildTree` method, whose internals this documentation does not describe, with the organization id and `false`, and adds to the [parent tree](#parent-tree) to form the [natural tree](#natural-tree) (`OrganizationStructureProvider#getNaturalTree(String)`). `OrganizationStructureProvider#getNaturalTree(String)` makes that call only when the provider has a node for the organization, and otherwise returns a set that holds only the passed id (`OrganizationStructureProvider#getNaturalTree(String)`). Because `OBContext#setReadableOrganizations(Role)` unions the natural trees of the [active organizations](#active-organization) of the role unless they include `"0"`, the child tree of each of those organizations is part of the [readable organizations](#readable-organizations) (`OBContext#setReadableOrganizations(Role)`).

Used in: [04-security-and-filtering](./04-security-and-filtering.md#readable-and-writable-sets)

### Client

A client is the record that a business object of a [client-enabled entity](#client-enabled-entity) references through its property named `client`; `Property#initializeName` sets the entity's client-enabled flag when it finds that property (`Property#initializeName`). `OBContext#initialize(String, String, String, String, String, String)` resolves the current client of the [user context](#user-context), and `OBContext#setReadableClients(Role)` computes the [readable clients](#readable-clients) from the [role](#role) (`OBContext#initialize(String, String, String, String, String, String)`, `OBContext#setReadableClients(Role)`). When the context is outside admin mode or the [org/client access check](#orgclient-access-check) is on, `SecurityChecker#checkWriteAccess(Object, boolean)`, reached through `SecurityChecker#checkWriteAccess(Object)`, requires the client of a client-enabled object to equal `OBContext#getCurrentClient()`, and `OBDal#save(Object)` fills a missing client with a [proxy](#proxy) of the current client (`SecurityChecker#checkWriteAccess(Object)`, `SecurityChecker#checkWriteAccess(Object, boolean)`, `OBDal#setClientOrganization`).

- Code qualification: filtering by client is applied by `OBCriteria#initialize` and `OBQuery#addOrgClientActiveFilter`, and only for client-enabled entities (`OBCriteria#initialize`, `OBQuery#addOrgClientActiveFilter`). The filter can be switched off per query with `OBCriteria#setFilterOnReadableClients(boolean)` or `OBQuery#setFilterOnReadableClients(boolean)` (`OBCriteria#setFilterOnReadableClients(boolean)`, `OBQuery#setFilterOnReadableClients(boolean)`). It is added in admin mode too, because in `OBCriteria#initialize` and `OBQuery#createQueryString` only the read check depends on `OBContext#isInAdministratorMode()`, and `OBQuery#addOrgClientActiveFilter`, which `OBQuery#createQueryString` calls after that check in either mode, does not test it (`OBCriteria#initialize`, `OBQuery#createQueryString`, `OBQuery#addOrgClientActiveFilter`). `OBDal#get(Class, Object)` and `OBDal#get(String, Object)` add no row filter and perform only the entity-level read check (`OBDal#get(Class, Object)`, `OBDal#get(String, Object)`).

Used in: [01-architecture](./01-architecture.md#per-entity-rules), [02-runtime-model](./02-runtime-model.md#access-level), [03-dal-service-api](./03-dal-service-api.md#reading-guide), [04-security-and-filtering](./04-security-and-filtering.md#reading-guide)

### Client administrator

A client administrator is a [role](#role) that the generated `Role` class (boundary) flags as client administrator; `SecurityChecker#checkWriteAccess(Object)`, through the private `SecurityChecker#checkWriteAccess(Object, boolean)` to which it delegates, reads the flag from the role of the current [user context](#user-context), and no other documented method reads it (`SecurityChecker#checkWriteAccess(Object)`, `SecurityChecker#checkWriteAccess(Object, boolean)`). When the object being written belongs to table `AD_Role_OrgAccess`, the role of the context is a client administrator and the client of that role equals the client of the object, `SecurityChecker#checkWriteAccess(Object, boolean)` skips the [writable organizations](#writable-organizations) test, an exception that its source comment ties to issue 23419 (`SecurityChecker#checkWriteAccess(Object, boolean)`). The exception applies only within the client, entity and organization tests, which run when the object has a client and the context is outside [admin mode](#admin-mode) or the [org/client access check](#orgclient-access-check) is on (`SecurityChecker#checkWriteAccess(Object, boolean)`).

Used in: [04-security-and-filtering](./04-security-and-filtering.md#what-admin-mode-skips)

### Client-enabled entity

A client-enabled entity is an [entity](#entity) with a property named `client`: `Property#initializeName` sets the entity's client-enabled flag and marks the property as a client-or-organization property when it finds that name, and `Entity#isClientEnabled` returns the flag (`Property#initializeName`, `Entity#isClientEnabled`). `Entity#getImplementsStatement` adds `ClientEnabled` (boundary) to the interfaces of the entity's [generated class](#generated-class), and `OBDal#save(Object)`, through `OBDal#setClientOrganization`, fills a missing [client](#client) of an object that implements it with a [proxy](#proxy) of the current client of `OBContext` (`Entity#getImplementsStatement`, `OBDal#setClientOrganization`). Outside admin mode, or while the [org/client access check](#orgclient-access-check) is on, `SecurityChecker#checkWriteAccess(Object)`, through the private `SecurityChecker#checkWriteAccess(Object, boolean)` to which it delegates, requires a client set on such an object to equal `OBContext#getCurrentClient()` (`SecurityChecker#checkWriteAccess(Object)`, `SecurityChecker#checkWriteAccess(Object, boolean)`). While the `setFilterOnReadableClients(boolean)` switch is on, `OBCriteria#initialize` and `OBQuery#addOrgClientActiveFilter` restrict `client.id` of a client-enabled entity to the [readable clients](#readable-clients) (`OBCriteria#initialize`, `OBQuery#addOrgClientActiveFilter`). The separate `_ComputedColumns` class mapping of an entity with [computed columns](#computed-column) gets a read-only many-to-one for the client when the entity is client-enabled (`DalMappingGenerator#generateComputedColumnsClassMapping`).

Used in: [01-architecture](./01-architecture.md#per-entity-rules), [02-runtime-model](./02-runtime-model.md#flags), [03-dal-service-api](./03-dal-service-api.md#obdalsaveobject), [04-security-and-filtering](./04-security-and-filtering.md#client-organization-and-active-filtering)

### Composite id

A composite id is the id of an entity that has several id properties: `ModelProvider#createCompositeId` creates a property named `id` whose id parts are the former id properties, each marked as part of the composite id (`ModelProvider#createCompositeId`). Its type name is the entity class name plus `.Id`, and its formatted default value is `new Id()` (`Property#getTypeName`, `Property#getFormattedDefaultValue`). `DalMappingGenerator#generateCompositeID` maps it as `<composite-id name="id">` with the class `<ClassName>$Id`, a `<key-property>` for each primitive part and a `<key-many-to-one>` for each reference part, and `DalMappingGenerator#generateMapping(Entity)` does not emit the parts as ordinary properties (`DalMappingGenerator#generateCompositeID`, `DalMappingGenerator#generateMapping(Entity)`).

Used in: [01-architecture](./01-architecture.md#which-entities-are-mapped), [02-runtime-model](./02-runtime-model.md#how-the-runtime-model-is-built)

### Computed column

A computed column is a property with [SQL logic](#sql-logic), for which `Property#isComputedColumn` is true; `Entity#hasComputedColumns` is true when at least one property of the entity is one (`Property#isComputedColumn`, `Entity#hasComputedColumns`). For such an entity `ModelProvider#initialize` adds a [virtual entity](#virtual-entity) whose name ends in `_ComputedColumns`, and `Entity#initialize(Table)` adds the [proxy](#proxy) property `_computedColumns` (`ModelProvider#initialize`, `Entity#initialize(Table)`). `DalMappingGenerator#generateComputedColumnsMapping` maps that property as a read-only [many-to-one](#many-to-one) on the id column, and `DalMappingGenerator#generateComputedColumnsClassMapping` appends the companion class mapping that holds the SQL-logic properties (`DalMappingGenerator#generateComputedColumnsMapping`, `DalMappingGenerator#generateComputedColumnsClassMapping`). `GenerateEntitiesTask#execute` writes a `<SimpleClassName>_ComputedColumns.java` class for an entity with computed columns (`GenerateEntitiesTask#execute`). `Entity#getRealProperties(boolean)` leaves computed columns out unless its argument is `true`, while its Javadoc describes the flag the other way round; 02 records this as an ambiguity (`Entity#getRealProperties`).

Used in: [01-architecture](./01-architecture.md#reading-guide), [02-runtime-model](./02-runtime-model.md#how-the-runtime-model-is-built)

### Criteria

A criteria is a Hibernate criteria query object: `OBCriteria` extends Hibernate's `CriteriaImpl` (boundary), and `OBDal#createCriteria(Class)` and its overloads run the read check and return an `OBCriteria` bound to the session of the instance's [pool](#pool) (`OBDal#createCriteria(Class)`). `OBCriteria#list()`, `OBCriteria#count()`, both `scroll` overloads and `OBCriteria#uniqueResult()` first call `OBCriteria#initialize` and then delegate to the superclass (`OBCriteria#list()`, `OBCriteria#count()`, `OBCriteria#scroll()`, `OBCriteria#scroll(ScrollMode)`, `OBCriteria#uniqueResult()`, `OBCriteria#initialize`). Outside admin mode `OBCriteria#initialize` runs the read check, and in either mode it adds each of the organization, client and active restrictions only when its per-query switch is on and the entity has the matching capability: the organization restriction when the organization is part of the entity's key or the entity is organization-enabled, the client restriction when the entity is client-enabled, and the active restriction when the entity is active-enabled (`OBCriteria#initialize`). On a criteria it has already initialized and that has not been marked as modified since, `OBCriteria#initialize` returns at once without the read check or any restriction (`OBCriteria#initialize`). Only `OBCriteria#addOrderBy(String, boolean)` and the switch setters `OBCriteria#setFilterOnReadableOrganization(boolean)`, `OBCriteria#setFilterOnReadableClients(boolean)` and `OBCriteria#setFilterOnActive(boolean)` mark the criteria as modified, and when `OBCriteria#initialize` runs on an initialized criteria so marked, it logs a warning that filters may be duplicated and then runs again (`OBCriteria#initialize`, `OBCriteria#addOrderBy(String, boolean)`, `OBCriteria#setFilterOnReadableOrganization(boolean)`, `OBCriteria#setFilterOnReadableClients(boolean)`, `OBCriteria#setFilterOnActive(boolean)`).

Used in: [03-dal-service-api](./03-dal-service-api.md#reading-guide), [04-security-and-filtering](./04-security-and-filtering.md#criteria-restrictions)

### Cross-org reference admin mode

Cross-org reference admin mode is the mode that `OBContext#setCrossOrgReferenceAdminMode()` enters by pushing, onto a stack separate from the [admin mode stack](#admin-mode-stack), an entry that is not admin mode, keeps the org/client check and is marked as cross-org admin mode (`OBContext#setCrossOrgReferenceAdminMode()`). Its Javadoc states that the mode allows references from an object to another one outside the [natural tree](#natural-tree) of its organization, only for columns marked to allow it (`OBContext#setCrossOrgReferenceAdminMode()`). `OBContext#isInCrossOrgAdministratorMode()` is true while the top of that stack is such an entry, and `OBContext#restorePreviousCrossOrgReferenceMode()` pops it (`OBContext#isInCrossOrgAdministratorMode()`, `OBContext#restorePreviousCrossOrgReferenceMode()`). While the mode is on, the [cross-organization reference check](#cross-organization-reference-check) skips the properties that allow cross-organization references (`OBInterceptor#checkReferencedOrganizations`).

Used in: [04-security-and-filtering](./04-security-and-filtering.md#the-admin-mode-stack)

### Cross-organization reference check

The cross-organization reference check is `OBInterceptor#checkReferencedOrganizations`, which, for an organization-enabled object, throws `OBSecurityException` when a reference whose value is an organization-enabled business object or proxy, and not an `Organization`, points to an organization outside the [natural tree](#natural-tree) of the object's organization, as reported by `OrganizationStructureProvider#isInNaturalTree(Organization, Organization)` (`OBInterceptor#checkReferencedOrganizations`). It examines the changed references, or every reference when the object is new or its organization changed, and skips references to `AttributeSetInstance` (boundary) and to [virtual entities](#virtual-entity), audit-info and image properties, and properties that allow cross-organization references while [cross-org reference admin mode](#cross-org-reference-admin-mode) is on (`OBInterceptor#checkReferencedOrganizations`). `OBInterceptor#onFlushDirty` runs it unless `OBInterceptor#setDisableCheckReferencedOrganizations(boolean)` has set the thread-local switch to true (`OBInterceptor#onFlushDirty`, `OBInterceptor#setDisableCheckReferencedOrganizations`). The call for new records in `OBInterceptor#onSave` is commented out, so the check runs only from `OBInterceptor#onFlushDirty`, although the method still computes an `isNew` flag; 04 records this as an ambiguity (`OBInterceptor#onSave`, `OBInterceptor#checkReferencedOrganizations`).

Used in: [04-security-and-filtering](./04-security-and-filtering.md#interceptor-behavior)

### Data Access Layer (DAL)

The Data Access Layer (DAL) is the set of Openbravo classes that reads the [Application Dictionary](#application-dictionary-ad) into the [runtime model](#runtime-model), maps that model to Hibernate and gives application code its sessions and [business objects](#business-object): `ModelProvider#getModel` returns the runtime model, `DalSessionFactoryController#mapModel` registers the [Hibernate mapping](#hibernate-mapping) that `DalMappingGenerator#generateMapping()` produces, and `OBDal#getSession` returns the current Hibernate [session](#session) from `SessionHandler#getSession(String)` (`ModelProvider#getModel`, `DalSessionFactoryController#mapModel`, `OBDal#getSession`). The `OBDal` class Javadoc describes `OBDal` as the main external access to the Data Access Layer, with data access methods such as save, get, query and remove (`OBDal#getInstance()`). Its runtime classes form the model, structure, provider, core, service and security layers, grouped by the packages `org.openbravo.base.model`, `org.openbravo.base.structure`, `org.openbravo.base.provider`, `org.openbravo.dal.core`, `org.openbravo.dal.service` and `org.openbravo.dal.security`, as [01-architecture.md, Layers](./01-architecture.md#layers) describes (`ModelProvider#getModel`, `OBDal#getInstance()`). At [development time](#development-time), `GenerateEntitiesTask#main` writes the [generated classes](#generated-class) from the same runtime model (`GenerateEntitiesTask#execute`).

Used in: [01-architecture](./01-architecture.md#reading-guide), [02-runtime-model](./02-runtime-model.md#reading-guide), [03-dal-service-api](./03-dal-service-api.md#reading-guide)

### Data origin

The data origin is the value of an AD `Table` record that the runtime model compares with `Table`, `Datasource` and `HQL` to tell kinds of [entity](#entity) apart: `Entity#initialize(Table)` marks an entity as a [datasource-based entity](#datasource-based-entity) when the data origin of its table is `Datasource` and as an [HQL-based entity](#hql-based-entity) when it is `HQL`, and `ModelProvider#initialize` handles a table whose data origin is `Table` as the table of a [table-based entity](#table-based-entity) (`Entity#initialize(Table)`, `ModelProvider#initialize`). `ModelProvider#removeInvalidTables` drops a table whose data origin is `Table` when it has no [primary key](#primary-key) columns, logging a warning, and keeps every table with another data origin (`ModelProvider#removeInvalidTables`). `ModelProvider#initialize` indexes the tables whose data origin is `Table` by lower-cased table name and all other tables by lower-cased name, and indexes by table name only the entities of tables whose data origin is `Table` (`ModelProvider#initialize`). For an entity whose data origin is `Datasource` or `HQL`, `GenerateEntitiesTask#execute` writes no class, and `ModelProvider#initialize` does not call `ModelProvider#createPropertyInParentEntity` for it, so its own reference properties add no [child properties](#child-property) to the entities they reference, and it does not take its [mandatory flags](#mandatory-flag) from the database (`GenerateEntitiesTask#execute`, `ModelProvider#initialize`, `ModelProvider#createPropertyInParentEntity`).

Used in: [02-runtime-model](./02-runtime-model.md#how-the-runtime-model-is-built)

### Database trigger

A database trigger is a procedure that the database itself runs when rows of a table change; the documented DAL classes refer to database triggers only in the commit methods of `SessionHandler`, which refuse to commit while `TriggerHandler` (boundary) reports triggers as disabled (`SessionHandler#commitAndClose(String)`, `SessionHandler#commitAndStart()`). `SessionHandler#commitAndClose(String)` then fails through `Check.isFalse` with the message "Triggers disabled, commit is not allowed when in triggers-disabled mode, call TriggerHandler.enable() before committing", attempts a rollback of the [transaction](#transaction), ignoring any error from that attempt, and lets the failure propagate once the connection and the session have been closed (`SessionHandler#commitAndClose(String)`). `SessionHandler#commitAndStart()` makes the same check before it commits (`SessionHandler#commitAndStart()`), and `OBDal#commitAndClose()` reaches the check because, when the thread's [session handler](#session-handler) is present and available for the `OBDal` instance's [pool](#pool) (`SessionHandler#isSessionHandlerPresent(String)`), it calls `SessionHandler#commitAndClose(String)` (`OBDal#commitAndClose()`).

Used in: [01-architecture](./01-architecture.md#commit-rollback-and-flush)

### Datasource-based entity

A datasource-based entity is an entity whose AD table has the [data origin](#data-origin) `Datasource`; `Entity#initialize(Table)` sets its datasource-based flag, read by `Entity#isDataSourceBased()`, from that value (`Entity#initialize(Table)`). `GenerateEntitiesTask#execute` writes no class for it, `DalMappingGenerator#generateMapping()` does not map it, and `ModelProvider#initialize` does not call `ModelProvider#createPropertyInParentEntity` for it, so its own reference properties add no [child properties](#child-property) to the entities they reference, and it does not take its [mandatory flags](#mandatory-flag) from the database (`GenerateEntitiesTask#execute`, `DalMappingGenerator#generateMapping()`, `ModelProvider#initialize`, `ModelProvider#createPropertyInParentEntity`).

Used in: [01-architecture](./01-architecture.md#which-entities-are-mapped), [02-runtime-model](./02-runtime-model.md#how-the-runtime-model-is-built)

### Deactivated organization

A deactivated organization is an organization of an active [role-organization assignment](#role-organization-assignment) of the current [role](#role) whose organization record is inactive, or, for an [automatic role](#automatic-role), an organization that `RoleAccessUtils` (boundary) returns; `OBContext#getDeactivatedOrganizations()` computes the set on first use, caches it and returns a copy (`OBContext#getDeactivatedOrganizations()`). `SecurityChecker#checkWriteAccess(Object, boolean)`, reached through `SecurityChecker#checkWriteAccess(Object)`, lets an `Organization` object that is among the deactivated organizations pass the [writable organizations](#writable-organizations) test (`SecurityChecker#checkWriteAccess(Object, boolean)`). A deactivated organization can still be among the [readable organizations](#readable-organizations), because the `"0"` branch of `OBContext#setReadableOrganizations(Role)` selects the organizations of the client with no condition on the active flag (`OBContext#getOrganizations(Client)`).

Used in: [04-security-and-filtering](./04-security-and-filtering.md#reading-guide)

### Derived readable

An entity is derived readable for a role when the `EntityAccessChecker` of the context classifies it so: per the Javadoc of `EntityAccessChecker#initialize`, the checker computes the readable, writable, non-readable and derived-readable entities from the windows available to the role (`EntityAccessChecker#initialize`). `EntityAccessChecker#isDerivedReadable(Entity)` reports the classification and returns false before the checker is initialized and in admin mode (`EntityAccessChecker#isDerivedReadable`). When a property is read or set, `BaseOBObject#checkDerivedReadable` checks only if the object is not marked allow-read through `BaseOBObject#setAllowRead(boolean)` and the current `OBContext` exists, is initialized and is outside admin mode (`BaseOBObject#get(String, Language, String)`, `BaseOBObject#set(String, Object)`, `BaseOBObject#checkDerivedReadable`). The first such check on an object, while its private `isDerivedReadable` field is still null, stores in that field the result of `EntityAccessChecker#isDerivedReadable(Entity)` from the current context's checker for the object's entity (`BaseOBObject#checkDerivedReadable`). That is the field's only assignment, so later checks on the same object reuse the stored value, true or false, without consulting the checker, whichever context is current then (`BaseOBObject#checkDerivedReadable`). The check throws `OBSecurityException` when the stored value is true and `Property#allowDerivedRead` is false for the property read or set (`BaseOBObject#checkDerivedReadable`). `Property#allowDerivedRead` is true for the active column, [audit properties](#audit-properties), id and [identifier](#identifier) properties, client and organization properties, and properties that another property references (`Property#allowDerivedRead`). When the `hb.generate.all.parent.child.properties` setting is false, `ModelProvider#createPropertyInParentEntity` generates no [child property](#child-property) in the parent entity for an existing referencing property of a child entity that only that setting would make eligible, yet still flags that referencing property as being referenced; its source comment gives the reason: the flag affects `BaseOBObject#checkDerivedReadable` (`ModelProvider#initialize`, `ModelProvider#createPropertyInParentEntity`). `EntityAccessChecker#initialize` puts the entities that the role's table access excludes among the non-readable entities and removes them from the readable ones, and then adds every target entity of a readable entity's properties that is not itself readable to the derived-readable entities without consulting the non-readable ones, so an entity can be both non-readable and derived readable (`EntityAccessChecker#initialize`). Before the checker is initialized and in admin mode, `EntityAccessChecker#checkReadable(Entity)` returns without checking; otherwise it throws `OBSecurityException` for a non-readable entity before it accepts a derived-readable one, so a derived-readable classification does not override a non-readable one, and it then accepts a readable or derived-readable entity and throws `OBSecurityException` for any other (`EntityAccessChecker#checkReadable`).

Used in: [02-runtime-model](./02-runtime-model.md#derived-read), [04-security-and-filtering](./04-security-and-filtering.md#checkers-and-structure-providers)

### Development time

Development time is the build phase in which `GenerateEntitiesTask#main`, started by `src/build.xml#generate.entities.quick`, writes the [generated classes](#generated-class), as opposed to the runtime in which the remaining DAL classes run inside the application (`GenerateEntitiesTask#main`). At development time `GenerateEntitiesTask#execute` reads the same [runtime model](#runtime-model) that the running application uses, through `ModelProvider#getModel` (`GenerateEntitiesTask#execute`).

Used in: [01-architecture](./01-architecture.md#reading-guide)

### Dirty check

A dirty check asks whether a Hibernate [session](#session) holds unflushed changes: `SessionHandler#isSessionDirty(String)` asks Hibernate for the pool's session while a thread-local flag is set, and `OBInterceptor#onFlushDirty` returns false at once while `SessionHandler#isCheckingDirtySession()` reports that flag (`SessionHandler#isSessionDirty(String)`, `OBInterceptor#onFlushDirty`). The Javadoc of `SessionHandler#isSessionDirty(String)` gives the reason: calling `isDirty()` on the Hibernate `Session` (boundary) directly triggers the [entity persistence observers](#entity-persistence-observer) of modified entities, and this method handles the check so that they are not called (`SessionHandler#isSessionDirty(String)`). `OBDal#isSessionDirty()` returns the result for the instance's [pool](#pool), and `SessionHandler#flushRemainingChanges` flushes again while it reports changes (`OBDal#isSessionDirty()`, `SessionHandler#flushRemainingChanges`).

Used in: [01-architecture](./01-architecture.md#dirty-check), [03-dal-service-api](./03-dal-service-api.md#obdalissessiondirty), [04-security-and-filtering](./04-security-and-filtering.md#callbacks)

### Domain type

A domain type is the class behind an AD reference that the runtime model uses for the type of a property: `ModelProvider#initialize` sets the model provider on the domain type of each reference and initializes it, and `Property#initializeFromColumn(Column, boolean)`, to which `Property#initializeFromColumn(Column)` delegates, copies the domain type from the column (`ModelProvider#initialize`, `Property#initializeFromColumn(Column)`, `Property#initializeFromColumn(Column, boolean)`). `Property#isPrimitive` is true when the domain type is a `PrimitiveDomainType`, `Property#checkIsValidValue` lets the domain type check a value, and the [child properties](#child-property) use `OneToManyDomainType` (`Property#isPrimitive`, `Property#checkIsValidValue`, `ModelProvider#createChildProperty`). `ModelProvider#initializeReferenceClasses` loads the [reference implementation classes](#reference-implementation-class) and, for each class assignable to `BaseDomainType` (boundary), registers the classes returned by its `getClasses()` with the [model session factory](#model-session-factory) (`ModelProvider#initializeReferenceClasses`). `src/build.xml#compile.src.gen` compiles the domain types of modules before generation runs (`src/build.xml#compile.src.gen`).

Used in: [01-architecture](./01-architecture.md#entity-generation-generateentities), [02-runtime-model](./02-runtime-model.md#reading-guide)

### Dynamic API

The dynamic API reads and writes the values of a [business object](#business-object) by property name through `BaseOBObject#get(String)` and `BaseOBObject#set(String, Object)`, the methods that `DynamicEnabled` and `BaseOBObjectDef` declare (`BaseOBObject#get(String)`, `BaseOBObject#set(String, Object)`). A read resolves the property with `Entity#getProperty(String)`, which throws `CheckException` for an unknown name, and runs `BaseOBObject#checkDerivedReadable` (`BaseOBObject#get(String, Language, String)`). A write runs `Property#checkIsValidValue`, `BaseOBObject#checkDerivedReadable` and `Property#checkIsWritable`, in that order, before it stores the value with `BaseOBObject#setValue` (`BaseOBObject#set`). `BaseOBObject#getValue(String)` and `BaseOBObject#setValue(String, Object)` give unchecked access by name, and `OBDal#get(String, Object)` loads an object by [entity name](#entity-name) for use with this API (`BaseOBObject#getValue`, `OBDal#get(String, Object)`). Writing a value of an [inactive property](#inactive-property) through it throws `ValidationException` (`Property#checkIsWritable`).

Used in: [02-runtime-model](./02-runtime-model.md#reading-guide), [04-security-and-filtering](./04-security-and-filtering.md#access-checks)

### DynamicOBObject

`DynamicOBObject` is the class that, per the Javadoc of `Entity#getMappingClass`, the system uses as the runtime class of an entity whose generated class cannot be loaded, in which case `Entity#getMappingClass` returns null (`Entity#getMappingClass`). It is a boundary class, and this documentation states nothing about its type hierarchy or its members (`Entity#getMappingClass`). `DalMappingGenerator#generateMapping()` does not map an entity whose `Entity#getMappingClass()` returns null (`DalMappingGenerator#generateMapping()`).

Used in: [02-runtime-model](./02-runtime-model.md#mapping-class-and-generated-interfaces)

### Entity

An entity is the runtime-model object of class `Entity` that models one AD table; `Entity#initialize(Table)` sets its table name and table id, sets its class name to the table's package name, a dot and its class name, and sets its [entity name](#entity-name) from the name of the AD table record (`Entity#initialize(Table)`). It holds the [properties](#property) created from the table's columns and those added later, listed by `Entity#getProperties`, and the client-enabled, organization-enabled, active-enabled, view, datasource-based and HQL-based flags that the DAL tests (`Entity#getProperties`, `Entity#initialize(Table)`). `ModelProvider#getModel` returns the [runtime model](#runtime-model) as the list of entities, and `ModelProvider#getEntity(String)` looks one up by entity name, throwing `CheckException` for an unknown name (`ModelProvider#getModel`, `ModelProvider#getEntity(String)`). The kinds are [table-based entities](#table-based-entity), [view entities](#view-entity), [datasource-based entities](#datasource-based-entity), [HQL-based entities](#hql-based-entity) and [virtual entities](#virtual-entity) (`Entity#initialize(Table)`, `Entity#initializeComputedColumns`).

Used in: [01-architecture](./01-architecture.md#reading-guide), [02-runtime-model](./02-runtime-model.md#reading-guide), [03-dal-service-api](./03-dal-service-api.md#reading-guide), [04-security-and-filtering](./04-security-and-filtering.md#reading-guide)

### Entity access

Entity access is the role-level decision whether an entity may be read or written, made by the `EntityAccessChecker` that `OBContext#getEntityAccessChecker` creates on first use through `OBProvider#get(Class)` and initializes with the role id and the context (`OBContext#getEntityAccessChecker`). `EntityAccessChecker#checkReadable(Entity)` throws `OBSecurityException` when the entity is non-readable for the role, or neither readable nor [derived readable](#derived-readable); outside admin mode it is called through the private `OBDal#checkReadAccess(String)`, directly or through `OBDal#checkReadAccess(Class)`, from `OBDal#get(Class, Object)`, `OBDal#get(String, Object)` and every `OBDal#createQuery` and `OBDal#createCriteria` overload, and directly from `OBCriteria#initialize` and `OBQuery#createQueryString` (`EntityAccessChecker#checkReadable`, `OBDal#checkReadAccess(Class)`, `OBDal#checkReadAccess(String)`). `EntityAccessChecker#checkWritable(Entity)` throws `OBSecurityException` when `EntityAccessChecker#isWritable(Entity)` is false, and `OBDal#save(Object)` calls it outside admin mode (`EntityAccessChecker#checkWritable`, `OBDal#save(Object)`). `OBDal#checkReadAccess(String)` exempts the Client and Organization entities from the read check, while `OBCriteria#initialize` and `OBQuery#createQueryString` do not; 04 records this as an ambiguity (`OBDal#checkReadAccess(String)`). `OBContext#setRole(Role)` discards the cached checker so that it is recomputed on next use (`OBContext#setRole(Role)`).

Used in: [04-security-and-filtering](./04-security-and-filtering.md#reading-guide)

### Entity name

The entity name is the name under which the runtime model, the [Hibernate mapping](#hibernate-mapping) and the DAL services identify an entity; `Entity#initialize(Table)` takes it from the name of the AD table record through `Entity#setName`, which drops illegal characters with `Entity#removeIllegalChars`, and `DalMappingGenerator#generateMapping(Entity)` writes it into the class mapping (`Entity#initialize(Table)`, `Entity#removeIllegalChars`, `DalMappingGenerator#generateMapping(Entity)`). `ModelProvider#getEntity(String)` looks entities up by it, and `SessionHandler#save(String, Object)` passes it to Hibernate's `saveOrUpdate` for an `Identifiable` object (`ModelProvider#getEntity(String)`, `SessionHandler#save(String, Object)`). A generated class exposes it in a public static `ENTITY_NAME` field, which `DalUtil#getEntityName(Class)` reads through reflection, and `DalUtil#getEntityName(Object)` resolves it for a Hibernate [proxy](#proxy) without loading the object (`DalUtil#getEntityName(Class)`, `DalUtil#getEntityName(Object)`). `OBInterceptor#getEntityName(Object)` returns it for a `BaseOBObject` and null for any other object (`OBInterceptor#getEntityName`).

Used in: [01-architecture](./01-architecture.md#layers), [02-runtime-model](./02-runtime-model.md#looking-up-the-model), [03-dal-service-api](./03-dal-service-api.md#obdalsaveobject), [04-security-and-filtering](./04-security-and-filtering.md#callbacks)

### Entity persistence observer

An entity persistence observer is, in the Javadoc of `SessionHandler#isSessionDirty(String)`, code that runs for modified entities when `isDirty()` is invoked on the Hibernate `Session` (boundary); the Javadoc says that `isDirty()` should therefore not be invoked directly, and that `SessionHandler#isSessionDirty(String)` handles the check so that these observers are not called (`SessionHandler#isSessionDirty(String)`). That method asks Hibernate while a thread-local flag is set, and `OBInterceptor#onFlushDirty` returns false at once while `SessionHandler#isCheckingDirtySession()` reports the flag; its comment says the callback runs on actual flushes and also while the session is checked for dirtiness, and must do nothing in the latter case (`SessionHandler#isSessionDirty(String)`, `OBInterceptor#onFlushDirty`). `OBDal#isSessionDirty()` returns the result of the same [dirty check](#dirty-check) for its instance's [pool](#pool), and its Javadoc warns that `isDirty` should not be invoked directly on the Hibernate session (`OBDal#isSessionDirty()`).

Used in: [01-architecture](./01-architecture.md#dirty-check), [03-dal-service-api](./03-dal-service-api.md#obdalissessiondirty), [04-security-and-filtering](./04-security-and-filtering.md#callbacks)

### Event handler

An event handler, in the source comment of `SessionHandler#flushRemainingChanges`, is a business event handler that can change data while a session is flushed (`SessionHandler#flushRemainingChanges`). For that reason `SessionHandler#flushRemainingChanges` calls `OBDal#flush()` again while `SessionHandler#isSessionDirty(String)` reports changes, so that the session is really clean before the commit, and after more than 100 flushes it logs "Infinite loop in flushing session, tried more than 100 flushes" and stops looping without throwing (`SessionHandler#flushRemainingChanges`).

Used in: [01-architecture](./01-architecture.md#commit-rollback-and-flush)

### External connection pool

The external connection pool is the database connection pool that `SessionHandler` takes connections from when the `db.externalPoolClassName` setting is present and not empty and the pool loads: an instance initializer of `SessionHandler` then assigns its static `externalConnectionPool` field from `ExternalConnectionPool.getInstance` (boundary), and when loading fails it sets the field to null and, when debug logging is disabled, logs at info level that the external connection pool could not be loaded and the old pool is used, or, when debug logging is enabled, logs the warning "External connection pool class not found" with the exception (instance initializer read by `SessionHandler#createSession(String)`). While the field is set, `SessionHandler#createSession(String)` obtains a connection from `SessionHandler#getNewConnection(String)` for a [pool](#pool) that has none, stores it for that pool and opens the pool's [session](#session) with it, wrapping an `SQLException` in `OBException` with the message "Could not get connection to create DAL session" (`SessionHandler#createSession(String)`). `SessionHandler#getNewConnection(String)` takes the connection from the external connection pool and tries to disable its auto-commit; an `SQLException` from that attempt is logged with the message "Error setting connection to auto-commit mode", and the connection is still returned (`SessionHandler#getNewConnection(String)`). Without an external connection pool, it obtains a connection from the JDBC connection access of `DalSessionFactory` and initializes it with `DalSessionFactory#initConnection` (`SessionHandler#getNewConnection(String)`).

Used in: [01-architecture](./01-architecture.md#external-connection-pool)

### Fetch size

The fetch size is the value that `OBQuery#setFetchSize(int)` stores and `OBQuery#getFetchSize()` returns; `OBQuery#createQuery(Class)` applies it to the Hibernate query it creates when the value is above `-1` (`OBQuery#setFetchSize(int)`, `OBQuery#createQuery(Class)`). `OBQuery#count()` does not apply it (`OBQuery#count()`).

Used in: [03-dal-service-api](./03-dal-service-api.md#obquerycount)

### Flush

A flush writes the pending changes of a Hibernate [session](#session) to the database: `OBDal#flush()` flushes the session of the instance's [pool](#pool) when the current thread's `SessionHandler` is present and available for it, and first passes the connection to `SessionInfo.saveContextInfoIntoDB` (boundary) when the session is dirty (`OBDal#flush()`). `SessionHandler#begin(String)` gives each session the [flush mode](#flush-mode) `FlushMode.COMMIT`, and `SessionHandler#commitAndClose(String)` calls `SessionHandler#flushRemainingChanges`, which flushes repeatedly while the session is dirty (`SessionHandler#begin(String)`, `SessionHandler#flushRemainingChanges`). After a flush, `OBInterceptor#postFlush` clears the [new object](#new-object) flag of every flushed object (`OBInterceptor#postFlush`). The `LocalInterceptor` of the [model session factory](#model-session-factory) fails on every dirty flush, which keeps the model session read-only (`ModelSessionFactoryController#setInterceptor`).

Used in: [01-architecture](./01-architecture.md#commit-rollback-and-flush), [02-runtime-model](./02-runtime-model.md#how-the-runtime-model-is-built), [03-dal-service-api](./03-dal-service-api.md#obdalcommitandclose), [04-security-and-filtering](./04-security-and-filtering.md#callbacks)

### Flush mode

The flush mode is the Hibernate session setting that decides when the session is flushed; `SessionHandler#begin(String)` sets it to `FlushMode.COMMIT` on every session it creates for a [pool](#pool), before it begins the [transaction](#transaction) (`SessionHandler#begin(String)`). `SessionHandler#commitAndClose(String)` calls `SessionHandler#flushRemainingChanges` before it commits (`SessionHandler#commitAndClose(String)`).

Used in: [01-architecture](./01-architecture.md#request-lifecycle)

### Foreign key

A foreign key is a column that references the [primary key](#primary-key) of another table; when the id property of an entity is also a reference, a foreign key, the source comment in `ModelProvider#initialize` says that Hibernate requires two mappings, one for the id and one for the reference, and that the id generation strategy should be `foreign` (`ModelProvider#initialize`). `ModelProvider#setVirtualPropertiesForReferenceId` handles such entities: for an entity whose single id property is not primitive, `ModelProvider#createIdReferenceProperty` adds to that same entity a mandatory [one-to-one](#one-to-one) [reference property](#reference-property) on the id column, whose target is the entity the id referenced and whose referenced property is that entity's id property, and turns the original id into a [primitive property](#primitive-property) with the domain type of the target's id, whose `Property#getIdBasedOnProperty` is the new property and which no longer has a target entity (`ModelProvider#setVirtualPropertiesForReferenceId`, `ModelProvider#createIdReferenceProperty`). `DalMappingGenerator#generateStandardID` maps an id based on another property with a `foreign` generator whose `property` parameter names that property (`DalMappingGenerator#generateStandardID`).

Used in: [02-runtime-model](./02-runtime-model.md#how-the-runtime-model-is-built)

### FreeMarker template

A FreeMarker template is a template file of the FreeMarker template engine, which the class Javadoc of `GenerateEntitiesTask` names as the engine used to generate the entities; `GenerateEntitiesTask#execute` loads `entity.ftl` and `entityComputedColumns.ftl` from `org/openbravo/base/gen` under the base path through `GenerateEntitiesTask#createTemplateImplementation` (`GenerateEntitiesTask#execute`). `GenerateEntitiesTask#processTemplate` fills them to write each [generated class](#generated-class) and its `_ComputedColumns` companion class (`GenerateEntitiesTask#processTemplate`). A failure to load or process a template is wrapped in `IllegalStateException` and propagates, and the templates themselves are named as inputs only (`GenerateEntitiesTask#createTemplateImplementation`, `GenerateEntitiesTask#processTemplate`).

Used in: [01-architecture](./01-architecture.md#entity-generation-generateentities)

### generate.entities

`generate.entities` is the Ant target that regenerates the [generated classes](#generated-class): `build.xml#generate.entities` delegates to `src/build.xml#generate.entities`, which has no body and depends on `src/build.xml#clean.src.gen` and `src/build.xml#generate.entities.quick` (`build.xml#generate.entities`). The quick target depends on `src/build.xml#compile.src.gen`, runs `GenerateEntitiesTask#main` with the source path, the `src-gen` path and `config/Openbravo.properties`, and then compiles the generated sources (`src/build.xml#generate.entities.quick`). `GenerateEntitiesTask#execute` skips generation unless `GenerateEntitiesTask#hasChanged` is true, which happens when `src-gen/org/openbravo/model/ad` does not exist or holds a file older than the later of the model update time and the newest modification time of the generator source packages (`GenerateEntitiesTask#hasChanged`). It runs directly with `ant generate.entities`, and the root targets `build.xml#compile.war` and `build.xml#db.apply.modules.sampledata` call it, while `build.xml#smartbuild` and `build.xml#update.database` call the quick target (`build.xml#compile.war`, `build.xml#smartbuild`).

Used in: [01-architecture](./01-architecture.md#reading-guide), [02-runtime-model](./02-runtime-model.md#looking-up-the-model)

### Generated class

A generated class is the Java class that `GenerateEntitiesTask#execute` writes under [src-gen](#src-gen) for each entity that is neither datasource-based, HQL-based nor virtual, at the path given by `Entity#getClassName()` with dots replaced by slashes (`GenerateEntitiesTask#execute`, `Entity#getClassName`). Its `implements` clause and imports come from `Entity#getImplementsStatement` and `Entity#getJavaImports()`, whose Javadoc says it is used to generate the Java import statements during [generate.entities](#generateentities) and which delegates to `Entity#getJavaImports(List)` with all properties of the entity, and its accessor names from `Property#getGetterSetterName` (`Entity#getImplementsStatement`, `Entity#getJavaImports()`, `Entity#getJavaImports(List)`, `Property#getGetterSetterName`). Per the comment of `BaseOBObject#setDefaultValue`, a constructor of the generated class sets default data through that method without a security check (`BaseOBObject#setDefaultValue`). At run time `Entity#getMappingClass` loads it, and returns null when it cannot be loaded (`Entity#getMappingClass`). The generated sources are not in the repository, so `SystemInformation` is recorded as Not Found in [02-runtime-model.md, Worked example: SystemInformation](./02-runtime-model.md#worked-example-systeminformation), and generated classes named in 01 to 04, such as `User`, `Role`, `Organization` and `Client`, are boundary names (`GenerateEntitiesTask#execute`).

Used in: [01-architecture](./01-architecture.md#layers), [02-runtime-model](./02-runtime-model.md#reading-guide), [03-dal-service-api](./03-dal-service-api.md#reading-guide), [04-security-and-filtering](./04-security-and-filtering.md#reading-guide)

### hbm file

An hbm file is a Hibernate XML mapping file: `DalSessionFactoryController#mapModel` writes the string from `DalMappingGenerator#generateMapping()` to a temporary file with the suffix `.hbm`, adds it to the Hibernate `Configuration` and deletes it in a `finally` block, or adds the file named by the `hibernate.hbm.file` setting directly when that setting is present (`DalSessionFactoryController#mapModel`). A failure to write the temporary file raises `OBException`, while a failure to delete it is only logged (`DalSessionFactoryController#mapModel`). `DalMappingGenerator#generateMapping()` reads the file named by `hibernate.hbm.file` instead of generating the mapping when the file exists and `hibernate.hbm.readFile` is `true`, and when the setting is present and the mapping is generated it writes the result to that file (`DalMappingGenerator#generateMapping()`). Its source comment says that reading the file is useful while developing changes in the mapping (`DalMappingGenerator#generateMapping()`).

Used in: [01-architecture](./01-architecture.md#registering-the-mapping)

### Hibernate mapping

The Hibernate mapping is the XML that maps the entities of the [runtime model](#runtime-model) to their tables: `DalMappingGenerator#generateMapping()` iterates `ModelProvider#getModel`, maps every entity except [datasource-based entities](#datasource-based-entity), [virtual entities](#virtual-entity) and entities whose `Entity#getMappingClass()` returns null, and inserts the class mappings into the `template_main.hbm.xml` template (`DalMappingGenerator#generateMapping()`). `DalMappingGenerator#generateMapping(Entity)` emits each class mapping, with its id, properties, references, [bags](#bag), [computed column](#computed-column) mapping and, for an [active-enabled entity](#active-enabled-entity), the [active filter](#active-filter) definition (`DalMappingGenerator#generateMapping(Entity)`). `DalSessionFactoryController#mapModel` registers the result with Hibernate, directly or through an [hbm file](#hbm-file) (`DalSessionFactoryController#mapModel`).

Used in: [01-architecture](./01-architecture.md#reading-guide), [04-security-and-filtering](./04-security-and-filtering.md#the-session-active-filter)

### Hibernate state array

The Hibernate state array is the `currentState` array that Hibernate passes to the [interceptor](#interceptor) callbacks `OBInterceptor#onSave` and `OBInterceptor#onFlushDirty`, holding the current value of each property named at the same index of their `propertyNames` array, and that `OBInterceptor#doEvent` hands on to `OBInterceptor#onNew` and `OBInterceptor#onUpdate` (`OBInterceptor#onSave`, `OBInterceptor#onFlushDirty`, `OBInterceptor#doEvent`). `OBInterceptor#onNew` writes each null [audit property](#audit-properties), and a null client or organization, both into this array and into the object; its source comment gives the reason: the security check that follows reads the object before Hibernate copies the changes from the array into it (`OBInterceptor#onNew`). `OBInterceptor#onUpdate` writes the updated date and the updated-by user into the array only (`OBInterceptor#onUpdate`).

Used in: [04-security-and-filtering](./04-security-and-filtering.md#shared-event-handling)

### HQL

HQL is Hibernate's query language: `OBQuery` wraps an HQL [where clause](#where-clause) and [order by clause](#order-by-clause), and `OBQuery#createQueryString` builds the full HQL from them, wrapping the caller's clause in parentheses after `where`, running the read check outside admin mode and calling `OBQuery#addOrgClientActiveFilter`, which appends each of the organization, client and active restrictions only when its per-query switch is on and the entity has the matching capability: the organization restriction when the organization is part of the entity's key or the entity is organization-enabled, the client restriction when the entity is client-enabled, and the active restriction when the entity is active-enabled (`OBQuery#createQueryString`, `OBQuery#addOrgClientActiveFilter`). The source comment in `OBQuery#createQueryString` gives the reason for the parentheses: the clauses it adds must all be and-ed with the caller's clause (`OBQuery#createQueryString`). `OBDal#createQuery(Class, String)` and its overloads take that clause, and the source comment in `OBQuery#getWhereAndOrderBy()` says an upper-case `WHERE` keyword makes Hibernate's HQL parser throw an exception, so the getter replaces each occurrence of `WHERE` that has a space immediately before and after it with `where`, stores the result in the query and returns it, and leaves every other upper-case `WHERE`, such as one at the start of the clause, unchanged (`OBDal#createQuery(Class, String)`, `OBQuery#getWhereAndOrderBy()`). `OBQuery#createQuery(Class)` creates the Hibernate `Query` (boundary) from the built string (`OBQuery#createQuery(Class)`).

Used in: [03-dal-service-api](./03-dal-service-api.md#reading-guide), [04-security-and-filtering](./04-security-and-filtering.md#query-restrictions)

### HQL-based entity

An HQL-based entity is an entity whose AD table has the [data origin](#data-origin) `HQL`; `Entity#initialize(Table)` sets its HQL-based flag, read by `Entity#isHQLBased()`, from that value (`Entity#initialize(Table)`). `GenerateEntitiesTask#execute` writes no class for it, and `ModelProvider#initialize` does not call `ModelProvider#createPropertyInParentEntity` for it, so its own reference properties add no [child properties](#child-property) to the entities they reference, and it does not take its [mandatory flags](#mandatory-flag) from the database (`GenerateEntitiesTask#execute`, `ModelProvider#initialize`, `ModelProvider#createPropertyInParentEntity`).

Used in: [01-architecture](./01-architecture.md#entity-generation-generateentities), [02-runtime-model](./02-runtime-model.md#how-the-runtime-model-is-built)

### HTTP session

The HTTP session is the servlet session of a request, in which the [user context](#user-context) is stored under the attribute `#OBContext`: `OBContext#setOBContext(HttpServletRequest)` returns without action when the request has no HTTP session, creates and initializes a context through `OBContext#setFromRequest(HttpServletRequest)` when none is stored, and re-initializes a stored context from the request when its user, role, client or organization is unset or differs from a value present in the HTTP session (`OBContext#setOBContext(HttpServletRequest)`, `OBContext#isInSync(HttpServletRequest)`). `OBContext#setFromRequest(HttpServletRequest)` reads the `#AD_User_ID`, `#AD_Role_ID`, `#AD_Client_ID` and `#AD_Org_ID` session values (`OBContext#setFromRequest(HttpServletRequest)`). `OBContext#setOBContextInSession(HttpServletRequest, OBContext)` copies a context into the attribute: it returns without writing when the request has no HTTP session, it refuses with a warning to store the [admin context](#admin-context), it sets the new-UI flag of the context from the `#HIDE_BACKBUTTON` session attribute, and it writes the attribute only when the attribute holds a different object, while `DalRequestFilter#doFilter` calls it from its handler's `doFinal` hook only when `OBContext#getOBContext()` returns a context, as [04-security-and-filtering.md, Creating and installing a context](./04-security-and-filtering.md#creating-and-installing-a-context) details (`OBContext#setOBContextInSession(HttpServletRequest, OBContext)`, `DalRequestFilter#doFilter`). The `OBContext` class Javadoc states that the context can be serialized as part of the Tomcat persistent session mechanism, and `OBContext#readObject` re-runs initialization from the stored ids (`OBContext#readObject`).

Used in: [01-architecture](./01-architecture.md#request-lifecycle), [04-security-and-filtering](./04-security-and-filtering.md#creating-and-installing-a-context)

### Id-reference property

An id-reference property is the extra [reference property](#reference-property) that `ModelProvider#createIdReferenceProperty` adds to an entity whose single id property is a reference, a [foreign key](#foreign-key), instead of a [primitive property](#primitive-property); `ModelProvider#setVirtualPropertiesForReferenceId` calls it for each such entity (`ModelProvider#setVirtualPropertiesForReferenceId`, `ModelProvider#createIdReferenceProperty`). The new property is a mandatory [one-to-one](#one-to-one) property that is not an id, takes the column name, column id, domain type, identifier flag and parent flag of the id property, targets the id's target entity and references that entity's first id property, and is named after the class of the target without its package, with the first character lower-cased (`ModelProvider#createIdReferenceProperty`). The original id property then takes the domain type of the target's id property, loses its identifier flag, parent flag and target entity, and records the new property as the property its id is based on, which `Property#getIdBasedOnProperty` returns; the method fails with `Check.isTrue` when the target's id property is not primitive (`ModelProvider#createIdReferenceProperty`). The source comment in `ModelProvider#initialize` gives the reason for this virtual property: when the id property is also a reference, Hibernate requires two mappings, one for the id and one for the reference, and the id generation strategy should be set to `foreign` (`ModelProvider#initialize`). `DalMappingGenerator#generateStandardID` maps the id with a `foreign` generator whose `property` parameter names the id-reference property, and `DalMappingGenerator#generateReferenceMapping` maps the id-reference property as `<one-to-one constrained="true">` (`DalMappingGenerator#generateStandardID`, `DalMappingGenerator#generateReferenceMapping`).

Used in: [02-runtime-model](./02-runtime-model.md#naming-rules)

### Identifier

The identifier is the user-readable text of a [business object](#business-object): `Entity#initialize(Table)` collects the identifier properties of an entity from the columns flagged as identifier, sorted by sequence number, and `BaseOBObject#getIdentifier` returns the identifier that `IdentifierProvider` (boundary) computes for the object (`Entity#initialize(Table)`, `BaseOBObject#getIdentifier`). The Javadoc of `Identifiable` says that an identifiable object has a unique id, an entity name and a user-readable identifier (`Identifiable#getIdentifier`). `BaseOBObject#toString` includes the non-null values of the identifier properties, `DalUtil#sortByIdentifier(List)` sorts objects by the identifier, and `DalUtil#getValueFromPath` returns it for the path part `_identifier` (`BaseOBObject#toString`, `DalUtil#sortByIdentifier`, `DalUtil#getValueFromPath`).

Used in: [02-runtime-model](./02-runtime-model.md#identity-and-properties)

### IN clause

An IN clause is an [HQL](#hql) condition of the form `in (…)` that compares a value with a list of values: the deprecated `OBDal#getReadableOrganizationsInClause()` and `OBDal#getReadableClientsInClause()` return one that lists, each in single quotes, the [readable organizations](#readable-organizations) of `OBContext#getReadableOrganizations` or the [readable clients](#readable-clients) of `OBContext#getReadableClients`, for example `in ('1000000', '1000001')`, or `in ('')` when the array is empty (`OBDal#getReadableOrganizationsInClause()`, `OBDal#getReadableClientsInClause()`). Their Javadoc deprecates both with the advice to use a bind statement parameter instead, and names no replacement method (`OBDal#getReadableOrganizationsInClause()`, `OBDal#getReadableClientsInClause()`). The restrictions that `OBQuery#addOrgClientActiveFilter` appends test the same two sets with `in (:…)` and a [named parameter](#named-parameter) (`OBQuery#addOrgClientActiveFilter`).

Used in: [03-dal-service-api](./03-dal-service-api.md#obdalgetreadableorganizationsinclause)

### Inactive property

An inactive property is a property whose AD column is not active: `Property#initializeFromColumn(Column, boolean)` stores the inverted active flag of the column, which `Property#isInactive` reads (`Property#initializeFromColumn(Column, boolean)`). `Property#checkIsWritable` throws `ValidationException` with a message saying that the property is inactive and can therefore not be changed, and `BaseOBObject#set(String, Object)` calls it after `Property#checkIsValidValue` and `BaseOBObject#checkDerivedReadable`, so a write through the [dynamic API](#dynamic-api) fails for an inactive property (`Property#checkIsWritable`, `BaseOBObject#set`). In the [Hibernate mapping](#hibernate-mapping), `DalMappingGenerator#generatePrimitiveMapping` gives an inactive [primitive property](#primitive-property) `update="false"` and `insert="false"`, and `DalMappingGenerator#generateReferenceMapping` does the same for the [many-to-one](#many-to-one) of an inactive [reference property](#reference-property) (`DalMappingGenerator#generatePrimitiveMapping`, `DalMappingGenerator#generateReferenceMapping`).

Used in: [01-architecture](./01-architecture.md#per-entity-rules), [02-runtime-model](./02-runtime-model.md#validation), [04-security-and-filtering](./04-security-and-filtering.md#access-checks)

### Inherited access

Inherited access is an entity flag that `Property#initializeName` sets when the entity has a property named `inheritedFrom` that references the `ADRole` entity (`Property#initializeName`). When `Entity#isInheritedAccessEnabled` is true, `Entity#getImplementsStatement` adds `InheritedAccessEnabled` to the `implements` clause of the [generated class](#generated-class); none of the DAL classes cited in 02 tests for that interface (`Entity#getImplementsStatement`).

Used in: [02-runtime-model](./02-runtime-model.md#flags)

### Interceptor

An interceptor is an object whose callbacks Hibernate invokes when a session saves, flushes or deletes objects: `DalSessionFactoryController#setInterceptor` installs a new `OBInterceptor` on the Hibernate `Configuration` it receives (`DalSessionFactoryController#setInterceptor`). `OBInterceptor#doEvent`, called from `OBInterceptor#onSave` and, unless one of the early exits described below applies, from `OBInterceptor#onFlushDirty`, sets the [audit properties](#audit-properties) of a `Traceable` object, sets a null client and organization of a new object to proxies of the current ones through `OBInterceptor#onNew`, and runs `SecurityChecker#checkWriteAccess(Object)` (`OBInterceptor#doEvent`, `OBInterceptor#onNew`, `OBInterceptor#onSave`, `OBInterceptor#onFlushDirty`). `OBInterceptor#onFlushDirty` returns false at once while `SessionHandler#isCheckingDirtySession()` is true, as during a [dirty check](#dirty-check), and returns false with a warning when its `previousState` argument is null (`OBInterceptor#onFlushDirty`). Past these two exits, `OBInterceptor#onFlushDirty` calls `OBInterceptor#doEvent` and then runs the [cross-organization reference check](#cross-organization-reference-check) only while the thread-local switch set by `OBInterceptor#setDisableCheckReferencedOrganizations(boolean)` is unset or false, as [04-security-and-filtering.md, Callbacks](./04-security-and-filtering.md#callbacks) sets out (`OBInterceptor#onFlushDirty`, `OBInterceptor#setDisableCheckReferencedOrganizations(boolean)`). `OBInterceptor#onDelete` runs `SecurityChecker#checkDeleteAllowed(Object)`, and `OBInterceptor#postFlush` clears the [new object](#new-object) flag (`OBInterceptor#onDelete`, `OBInterceptor#postFlush`). The [model session factory](#model-session-factory) installs its own `LocalInterceptor`, which fails on every save, delete, dirty flush and collection change (`ModelSessionFactoryController#setInterceptor`).

Used in: [01-architecture](./01-architecture.md#layers), [02-runtime-model](./02-runtime-model.md#how-the-runtime-model-is-built), [04-security-and-filtering](./04-security-and-filtering.md#reading-guide)

### Interceptor listener

The interceptor listener is an optional second Hibernate `Interceptor` held by an `OBInterceptor`: `OBInterceptor#setInterceptorListener(Interceptor)` stores it, and `OBInterceptor#getInterceptorListener` returns it (`OBInterceptor#setInterceptorListener`, `OBInterceptor#getInterceptorListener`). When it is set, `OBInterceptor#onSave` forwards the callback to it after `OBInterceptor#doEvent`, `OBInterceptor#onDelete` after `SecurityChecker#checkDeleteAllowed(Object)`, and `OBInterceptor#onFlushDirty`, when it does not return early, after `OBInterceptor#doEvent` and the [cross-organization reference check](#cross-organization-reference-check), which `OBInterceptor#setDisableCheckReferencedOrganizations(boolean)` can switch off (`OBInterceptor#onSave`, `OBInterceptor#onDelete`, `OBInterceptor#onFlushDirty`). `OBInterceptor#onSave` and `OBInterceptor#onFlushDirty` then return true for a [traceable object](#traceable-object) and for an object that implements `ClientEnabled` or `OrganizationEnabled`, and the listener's result otherwise (`OBInterceptor#onSave`, `OBInterceptor#onFlushDirty`). `OBInterceptor#preFlush`, `OBInterceptor#afterTransactionBegin`, `OBInterceptor#beforeTransactionCompletion` and `OBInterceptor#afterTransactionCompletion` forward the call to it and then call the inherited `EmptyInterceptor` implementation (`OBInterceptor#preFlush`, `OBInterceptor#afterTransactionBegin`).

Used in: [04-security-and-filtering](./04-security-and-filtering.md#callbacks)

### Join

A join brings an entity that the queried entity references into the query, so that the query can use the referenced entity's properties; the `OBCriteria` class Javadoc states the design of its order-by convenience method: the entities referred to from the order by are joined automatically (`OBCriteria#addOrderBy(String, boolean)`, `OBCriteria#initialize`). `OBCriteria#addOrderBy(String, boolean)` records each order-by entry, and for an entry whose path contains a dot, `OBCriteria#initialize` creates an [alias](#alias) for the part before the last dot, which its source comment calls creating a join, and orders on the property after the last dot through that alias (`OBCriteria#addOrderBy(String, boolean)`, `OBCriteria#initialize`). The alias name this join receives is recorded as an unresolved ambiguity at [`OBCriteria#addOrderBy(String, boolean)`](./03-dal-service-api.md#obcriteriaaddorderbystring-boolean) (`OBCriteria#initialize`). The `OBQuery` class Javadoc states that it handles joins for order by clauses, and the source comments of `OBQuery#createQueryString` say that a leading alias is supported for joins and name `left join a left join b where …` among the cases whose where part it wraps in parentheses (`OBQuery#createQueryString`).

Used in: [03-dal-service-api](./03-dal-service-api.md#obcriteria)

### Lock

A lock here is a database row lock that the DAL takes on one persisted object: `OBDal#getObjectLockForNoKeyUpdate(T)` requires an entity with exactly one id property, evicts the object from the [session](#session), runs a native `SELECT ... FOR <lock type>` query on its id, with the lock type `UPDATE` when `DalConnectionProvider` (boundary) reports `ORACLE` and `NO KEY UPDATE` otherwise, and returns a new instance read for the same id (`OBDal#getObjectLockForNoKeyUpdate(T)`). Its Javadoc gives the reason for the weaker PostgreSQL lock: `FOR NO KEY UPDATE` lets other transactions insert child records while the parent is locked, and the method is a workaround until Hibernate issue HHH-13135 is fixed (`OBDal#getObjectLockForNoKeyUpdate(T)`). The same Javadoc states that the lock exists only in the database, where Hibernate cannot detect it, that state not persisted before the call is ignored, and that the returned instance must be used instead of the parameter (`OBDal#getObjectLockForNoKeyUpdate(T)`).

Used in: [03-dal-service-api](./03-dal-service-api.md#obdalgetobjectlockfornokeyupdatet)

### Mandatory flag

The mandatory flag is the boolean that `Property#isMandatory` returns for a [property](#property): `Property#initializeFromColumn(Column, boolean)` copies it from the AD column, and `ModelProvider#initialize` then overwrites it, for every property that is not one-to-many, with the database not-null value that `ModelProvider#getColumnMandatories` reads from the column metadata, as [02-runtime-model.md, Mandatory flag](./02-runtime-model.md#mandatory-flag) describes (`Property#initializeFromColumn(Column, boolean)`, `ModelProvider#initialize`, `ModelProvider#getColumnMandatories`). `ModelProvider#initialize` keeps the copied value for [view entities](#view-entity), for properties without a column name and for [datasource-based](#datasource-based-entity), [HQL-based](#hql-based-entity) and [virtual entities](#virtual-entity), and logs a warning when the database has no value for a property that is neither a [computed column](#computed-column) nor a [proxy](#proxy) (`ModelProvider#initialize`). The source comments give the reason: the AD mandatory value is used in the UI and is often true where the database column allows null, so the value is set on the basis of the real not-null in the database (`Property#initializeFromColumn(Column, boolean)`, `ModelProvider#initialize`). `DalMappingGenerator#generatePrimitiveMapping` and `DalMappingGenerator#generateReferenceMapping` add `not-null="true"` to the mapping of a mandatory property, `DalMappingGenerator#generateReferenceMapping` adds `cascade="persist"` to a mandatory parent reference, and `DalMappingGenerator#generateOneToMany` sets `not-null="true"` on the key of a [bag](#bag) whose referenced property is mandatory (`DalMappingGenerator#generatePrimitiveMapping`, `DalMappingGenerator#generateReferenceMapping`, `DalMappingGenerator#generateOneToMany`). The Javadoc of `Property#checkIsValidValue(Object)` says the method checks that a value is not null if the property is mandatory, while its body returns for every null value and a source comment marks the mandatory check as disabled; [02-runtime-model.md, Validation](./02-runtime-model.md#validation) records this as an ambiguity that it does not resolve (`Property#checkIsValidValue`).

Used in: [01-architecture](./01-architecture.md#per-entity-rules), [02-runtime-model](./02-runtime-model.md#how-the-runtime-model-is-built)

### Many-to-one

A many-to-one is the Hibernate reference mapping that `DalMappingGenerator#generateReferenceMapping` emits for every [reference property](#reference-property) with a target entity that is not [one-to-one](#one-to-one): it carries the target `entity-name`, a `column`, or a `formula` when [SQL logic](#sql-logic) is set, `not-null="true"` when the property is mandatory, `update="false"` and `insert="false"` when the property is [inactive](#inactive-property) or belongs to a [view entity](#view-entity), and a [property-ref](#property-ref) when the referenced property is not the target's id (`DalMappingGenerator#generateReferenceMapping`). `DalMappingGenerator#generateCompositeID` uses a `<key-many-to-one>` for each reference part of a [composite id](#composite-id), and `DalMappingGenerator#generateComputedColumnsMapping` maps the `_computedColumns` property as a many-to-one (`DalMappingGenerator#generateCompositeID`, `DalMappingGenerator#generateComputedColumnsMapping`).

Used in: [01-architecture](./01-architecture.md#per-entity-rules)

### Mapping class

The mapping class of an entity is the Java class that `Entity#getMappingClass` returns, which its Javadoc calls the Java class implementing the entity: on the first call the method loads the class named by `Entity#getClassName` through `OBClassLoader` (boundary) and caches the result, and it returns null when the class is not found (`Entity#getMappingClass`). For an entity that `GenerateEntitiesTask#execute` writes a class for, the class it looks for is that [generated class](#generated-class), written at the path given by `Entity#getClassName` (`GenerateEntitiesTask#execute`, `Entity#getClassName`). When no class is found, the Javadoc of `Entity#getMappingClass` states that the system uses a [DynamicOBObject](#dynamicobobject) as the runtime class (`Entity#getMappingClass`). `DalMappingGenerator#generateMapping()` maps no entity whose mapping class is null, and `DalMappingGenerator#generateMapping(Entity)` adds the class name to the `<class>` element of an entity that has one (`DalMappingGenerator#generateMapping()`, `DalMappingGenerator#generateMapping(Entity)`). `Property#initializeName` corrects each property name against a [property-name constant](#property-name-constant) of the mapping class, and `OBDal#createCriteria(String)` builds its `OBCriteria` from the name of the mapping class (`Property#initializeName`, `OBDal#createCriteria(String)`).

Used in: [01-architecture](./01-architecture.md#which-entities-are-mapped), [02-runtime-model](./02-runtime-model.md#mapping-class-and-generated-interfaces), [03-dal-service-api](./03-dal-service-api.md#obdalcreatecriteriastring)

### Model session factory

The model session factory is the Hibernate session factory of a `ModelSessionFactoryController`, which `ModelProvider#initialize` creates to read the [Application Dictionary](#application-dictionary-ad) instead of using the DAL [session factory](#session-factory), and closes in a `finally` block (`ModelProvider#initialize`). It maps the eight AD model classes `Column`, `Module`, `Package`, `Reference`, `RefList`, `RefSearch`, `RefTable` and `Table`, plus every class added through `ModelSessionFactoryController#addAdditionalClasses` (`ModelSessionFactoryController#mapModel`). Its `LocalInterceptor` fails with `Check.fail` on every save, delete, dirty flush and collection remove, recreate or update, so the model session is read-only (`ModelSessionFactoryController#setInterceptor`). The source comment in `ModelProvider#initialize` gives the reason for a separate factory: the DAL layer uses `ModelProvider`, so reading the model through the DAL would create a cyclic relation; the same comment speaks of using `SessionHandler` directly, while the code creates a `ModelSessionFactoryController` (`ModelProvider#initialize`). `ModelProvider#computeLastUpdateModelTime` also opens a session on a new `ModelSessionFactoryController` and closes it afterwards (`ModelProvider#computeLastUpdateModelTime`).

Used in: [01-architecture](./01-architecture.md#startup-sequence), [02-runtime-model](./02-runtime-model.md#how-the-runtime-model-is-built)

### Named parameter

A named parameter is a `:name` placeholder in an HQL clause whose value is bound by name: `OBQuery#setNamedParameter(String, Object)` puts one value into the parameter map of the query, and when the Hibernate query is created, `OBQuery#setParameters(Query)` binds a `Collection` or `String[]` value as a parameter list and any other value as a single parameter (`OBQuery#setNamedParameter(String, Object)`, `OBQuery#setParameters(Query)`). `OBDal#createQuery(Class, String, Map)` takes a whole map, and `OBQuery#setNamedParameters(Map)` stores a map without copying it (`OBDal#createQuery(Class, String, Map)`, `OBQuery#setNamedParameters(Map)`). `OBQuery#addOrgClientActiveFilter` records the [readable organizations](#readable-organizations) as the named parameter `_dal_readableOrganizations_dal_` when it adds the organization restriction, and the [readable clients](#readable-clients) as the named parameter `_dal_readableClients_dal_` when it adds the client restriction, through `OBQuery#setNamedParameter(String, Object)`, which `OBQuery#setParameters(Query)` binds when the Hibernate query is created (`OBQuery#addOrgClientActiveFilter`, `OBQuery#setNamedParameter(String, Object)`, `OBQuery#setParameters(Query)`). For a non-null, non-empty list, `OBQuery#setParameters(List)` rewrites each [positional parameter](#positional-parameter) as a named one, and a null or empty list changes nothing (`OBQuery#setParameters(List)`).

Used in: [03-dal-service-api](./03-dal-service-api.md#obdalcreatequeryclass-string-list), [04-security-and-filtering](./04-security-and-filtering.md#query-restrictions)

### Native query

A native query is an SQL query over database tables and columns that code passes to the `createNativeQuery` method of the Hibernate [session](#session), instead of an [HQL](#hql) query over entities: `ModelProvider#buildUniqueConstraints` and `ModelProvider#getColumnMandatories` read every [unique constraint](#unique-constraint) and the column not-null metadata from the database with native queries while `ModelProvider#initialize` builds the [runtime model](#runtime-model) (`ModelProvider#buildUniqueConstraints`, `ModelProvider#getColumnMandatories`). `OBDal#getObjectLockForNoKeyUpdate(T)` builds one over the entity's table and id column, `SELECT <id column> FROM <table> WHERE <id column> = :id FOR <lock type>`, with the lock type `UPDATE` when `DalConnectionProvider` (boundary) reports `ORACLE` and `NO KEY UPDATE` otherwise, and runs it for the object's id after evicting the object from the session (`OBDal#getObjectLockForNoKeyUpdate(T)`). The Javadoc of that method states that a lock created this way exists only in the database and cannot be detected by Hibernate (`OBDal#getObjectLockForNoKeyUpdate(T)`).

Used in: [02-runtime-model](./02-runtime-model.md#how-the-runtime-model-is-built), [03-dal-service-api](./03-dal-service-api.md#obdalgetobjectlockfornokeyupdatet)

### Natural tree

The natural tree of an organization is the organization together with its [parent tree](#parent-tree) and its [child tree](#child-tree), as `OrganizationStructureProvider#getNaturalTree(String)` returns it, or a set that holds only the passed id when the provider has no node for it (`OrganizationStructureProvider#getNaturalTree(String)`). `OBContext#setReadableOrganizations(Role)` builds the [readable organizations](#readable-organizations) as the union of the natural trees of the [active organizations](#active-organization) of the role, unless those organizations include `"0"` (`OBContext#setReadableOrganizations(Role)`). Once that `"0"` branch has stored every organization of the current client in the cached `organizationList` field through `OBContext#getOrganizations(Client)`, and until `OBContext#addWritableOrganization(String)` clears the field, `OBContext#getOrganizationList(Role, List, Set, boolean)` returns a copy of it as the active organizations of the role, so the organizations whose natural trees are united can be that client-wide list (`OBContext#getOrganizationList(Role, List, Set, boolean)`, `OBContext#getOrganizations(Client)`). [04-security-and-filtering.md, Readable and writable sets](./04-security-and-filtering.md#readable-and-writable-sets) records this reuse as an ambiguity that it does not resolve (`OBContext#setReadableOrganizations(Role)`). `OrganizationStructureProvider#isInNaturalTree(Organization, Organization)` is true when either id is `"0"`, and otherwise when the second organization is in the natural tree of the first, and the [cross-organization reference check](#cross-organization-reference-check) uses it (`OrganizationStructureProvider#isInNaturalTree`, `OBInterceptor#checkReferencedOrganizations`).

Used in: [04-security-and-filtering](./04-security-and-filtering.md#readable-and-writable-sets)

### New object

A new object is a [business object](#business-object) for which `BaseOBObject#isNewOBObject` is true, because its id is null or because `BaseOBObject#setNewOBObject` has set the new-object flag (`BaseOBObject#isNewOBObject`). The field comment gives the reason for the flag: it forces an insert of the object, which is useful when the id of an imported object should be preserved (`BaseOBObject#setNewOBObject`). `OBInterceptor#isTransient` returns true for a `BaseOBObject` whose id is set and whose flag is set, and null otherwise, which leaves the decision to Hibernate (`OBInterceptor#isTransient`). `OBInterceptor#postFlush` sets the flag back to false for every flushed object, and `OBInterceptor#onFlushDirty` logs a warning for an object without previous state, a case the warning attributes to an id set without `setNewObject(true)` (`OBInterceptor#postFlush`, `OBInterceptor#onFlushDirty`).

Used in: [02-runtime-model](./02-runtime-model.md#values-identity-and-the-new-object-flag), [04-security-and-filtering](./04-security-and-filtering.md#callbacks)

### One-to-many property

A one-to-many property is a property whose value is a list, flagged by `Property#isOneToMany`; in the model that `ModelProvider#initialize` builds, these properties are created by `ModelProvider#createChildProperty` on the parent entity, not from a column (`Property#isOneToMany`, `ModelProvider#createChildProperty`). `DalMappingGenerator#generateOneToMany` maps each one as an inverse [bag](#bag) keyed on the column of the referenced property (`DalMappingGenerator#generateOneToMany`). `Property#getFormattedDefaultValue` gives it the default `new ArrayList<Object>()` in the generated class (`Property#getFormattedDefaultValue`). `DalUtil#copy(BaseOBObject, boolean, boolean, Map)` copies a one-to-many list only when children are copied, the property is a child and its target entity is not a view (`DalUtil#copy(BaseOBObject, boolean, boolean, Map)`).

Used in: [01-architecture](./01-architecture.md#per-entity-rules), [02-runtime-model](./02-runtime-model.md#how-the-runtime-model-is-built)

### One-to-one

A one-to-one is the Hibernate reference mapping that `DalMappingGenerator#generateReferenceMapping` emits for a one-to-one property as `<one-to-one constrained="true">`, named after the simple name of its type with a lower-case first letter, with the target `entity-name` and a [property-ref](#property-ref) when the referenced property is not the target's id (`DalMappingGenerator#generateReferenceMapping`). `ModelProvider#createIdReferenceProperty` creates such a property for an entity with one non-primitive id property, as the reference half of the two mappings that an id which is also a [foreign key](#foreign-key) needs (`ModelProvider#createIdReferenceProperty`, `ModelProvider#initialize`).

Used in: [01-architecture](./01-architecture.md#per-entity-rules), [02-runtime-model](./02-runtime-model.md#how-the-runtime-model-is-built)

### Order by clause

The order by clause is the part of an [HQL](#hql) query that sorts its results: `OBQuery` stores it together with the [where clause](#where-clause) as one string, and `OBQuery#createQueryString` splits that string at its first `order by`, matched case-insensitively, and appends the order by part unchanged at the end of the query string, after the where clause and the client, organization and active restrictions (`OBQuery#setWhereAndOrderBy(String)`, `OBQuery#createQueryString`). `OBQuery#count()` drops the order by clause from the query it counts with, and `OBQuery#getRowNumber(String)` keeps it, so the row number follows the query's sorting (`OBQuery#count()`, `OBQuery#getRowNumber(String)`). `OBCriteria` takes its order instead from the entries recorded by `OBCriteria#addOrderBy(String, boolean)`, which `OBCriteria#initialize` turns into ascending or descending orders, with a [join](#join) for a dotted path (`OBCriteria#addOrderBy(String, boolean)`, `OBCriteria#initialize`).

Used in: [03-dal-service-api](./03-dal-service-api.md#reading-guide)

### Order-by property

An order-by property is a property whose column is named `line`, `seqno` or `lineno`, compared in lower case: `Property#initializeFromColumn(Column, boolean)` sets the order-by flag for such a column and clears it for any other, and `Property#isOrderByProperty` reads it (`Property#initializeFromColumn(Column, boolean)`). `Entity#initialize(Table)` collects the order-by properties of an entity in the list that `Entity#getOrderByProperties` returns (`Entity#initialize(Table)`). `DalMappingGenerator#generateOneToMany` gives the [bag](#bag) of a [one-to-many property](#one-to-many-property) an `order-by` attribute that lists the column of each order-by property of the target entity followed by `ASC`, and no `order-by` attribute when the target entity has none (`DalMappingGenerator#generateOneToMany`).

Used in: [01-architecture](./01-architecture.md#per-entity-rules), [02-runtime-model](./02-runtime-model.md#values-copied-from-the-column)

### Org/client access check

The org/client access check is the client and writable-organization part of `SecurityChecker#checkWriteAccess(Object)`, which only delegates to the private `SecurityChecker#checkWriteAccess(Object, boolean)` with `logError` set to `true` (`SecurityChecker#checkWriteAccess(Object)`). That part of `SecurityChecker#checkWriteAccess(Object, boolean)` runs, for an object that has a client, when the context is outside admin mode or `OBContext#doOrgClientAccessCheck()` is true (`SecurityChecker#checkWriteAccess(Object, boolean)`). `OBContext#doOrgClientAccessCheck()` is false when the top of the [admin mode stack](#admin-mode-stack) carries a false org/client flag, as `OBContext#setAdminMode()` and `OBContext#setAdminMode(boolean)` with `false` push it, or when the deprecated admin flag is set or the role is `"0"`, and true in every other case (`OBContext#doOrgClientAccessCheck()`). In admin mode `OBDal#save(Object)` records the value of `OBContext#doOrgClientAccessCheck()` on the object through `BaseOBObject#setAccessChecks(boolean, boolean)`, and `SecurityChecker#checkWriteAccess(Object, boolean)` later skips the writable-organization test for an object whose flag is false (`OBDal#save(Object)`, `SecurityChecker#checkWriteAccess(Object, boolean)`).

Used in: [02-runtime-model](./02-runtime-model.md#values-identity-and-the-new-object-flag), [03-dal-service-api](./03-dal-service-api.md#obdalsaveobject), [04-security-and-filtering](./04-security-and-filtering.md#initialization-order)

### Organization

An organization is the record that a business object of an [organization-enabled entity](#organization-enabled-entity) references through its property named `organization`; `Property#initializeName` sets the entity's organization-enabled flag when it finds that property, and also the [organization-part-of-key](#organization-part-of-key) flag when the property is an id or part of a [composite id](#composite-id) (`Property#initializeName`). `OBContext#initialize(String, String, String, String, String, String)` resolves the current organization of the [user context](#user-context), and `OBContext` computes the [readable organizations](#readable-organizations), [writable organizations](#writable-organizations) and [deactivated organizations](#deactivated-organization) from the [role](#role) (`OBContext#initialize(String, String, String, String, String, String)`, `OBContext#getReadableOrganizations()`). The readable and writable organizations start from the active organizations of the role, which `OBContext#getOrganizationList(Role, List, Set, boolean)` returns as a copy of the cached client-wide organization list once the `"0"` branch of `OBContext#setReadableOrganizations(Role)` has stored it and until `OBContext#addWritableOrganization(String)` clears it, while the deactivated organizations do not start from that list (`OBContext#getOrganizationList(Role, List, Set, boolean)`, `OBContext#getDeactivatedOrganizations()`). [04-security-and-filtering.md, Readable and writable sets](./04-security-and-filtering.md#readable-and-writable-sets) records this reuse as an ambiguity that it does not resolve (`OBContext#setReadableOrganizations(Role)`). When the context is outside admin mode or the [org/client access check](#orgclient-access-check) is on, `SecurityChecker#checkWriteAccess(Object)`, through `SecurityChecker#checkWriteAccess(Object, boolean)`, requires the organization of an object to be among the writable organizations, with three exceptions, and `OBDal#save(Object)` fills a missing organization with a [proxy](#proxy) of the current organization (`SecurityChecker#checkWriteAccess(Object, boolean)`, `OBDal#setClientOrganization`).

- Code qualification: filtering by organization is applied by `OBCriteria#initialize` and `OBQuery#addOrgClientActiveFilter`, and only for organization-enabled entities or entities whose organization is part of the key, which are restricted on `id.organization.id` instead of `organization.id` (`OBCriteria#initialize`, `OBQuery#addOrgClientActiveFilter`). The filter can be switched off per query with `OBCriteria#setFilterOnReadableOrganization(boolean)` or `OBQuery#setFilterOnReadableOrganization(boolean)` (`OBCriteria#setFilterOnReadableOrganization(boolean)`, `OBQuery#setFilterOnReadableOrganization(boolean)`). It is added in admin mode too, because in `OBCriteria#initialize` and `OBQuery#createQueryString` only the read check depends on `OBContext#isInAdministratorMode()`, and `OBQuery#addOrgClientActiveFilter`, which `OBQuery#createQueryString` calls after that check in either mode, does not test it (`OBCriteria#initialize`, `OBQuery#createQueryString`, `OBQuery#addOrgClientActiveFilter`). `OBDal#get(Class, Object)` and `OBDal#get(String, Object)` add no row filter and perform only the entity-level read check (`OBDal#get(Class, Object)`, `OBDal#get(String, Object)`).

Used in: [01-architecture](./01-architecture.md#per-entity-rules), [02-runtime-model](./02-runtime-model.md#access-level), [03-dal-service-api](./03-dal-service-api.md#reading-guide), [04-security-and-filtering](./04-security-and-filtering.md#reading-guide)

### Organization part of key

Organization part of key is the entity flag that `Property#initializeName` sets, together with the [organization-enabled](#organization-enabled-entity) flag, when the property named `organization` is an id property or part of a [composite id](#composite-id), and that `Entity#isOrganizationPartOfKey` returns (`Property#initializeName`, `Entity#isOrganizationPartOfKey`). For such an entity, while the `setFilterOnReadableOrganization(boolean)` switch is on, `OBCriteria#initialize` restricts `id.organization.id` instead of `organization.id` to the [readable organizations](#readable-organizations) (`OBCriteria#initialize`). `OBQuery#addOrgClientActiveFilter` makes the same distinction, putting `id.organization.id` instead of `organization.id` in its organization fragment, and records the readable organizations as the [named parameter](#named-parameter) `_dal_readableOrganizations_dal_` of that fragment through `OBQuery#setNamedParameter(String, Object)`, which `OBQuery#setParameters(Query)` binds when the Hibernate query is created (`OBQuery#addOrgClientActiveFilter`, `OBQuery#setNamedParameter(String, Object)`, `OBQuery#setParameters(Query)`).

Used in: [02-runtime-model](./02-runtime-model.md#naming-rules), [04-security-and-filtering](./04-security-and-filtering.md#client-organization-and-active-filtering)

### Organization-enabled entity

An organization-enabled entity is an [entity](#entity) with a property named `organization`: `Property#initializeName` sets the entity's organization-enabled flag and marks the property as a client-or-organization property when it finds that name, and `Entity#isOrganizationEnabled` returns the flag (`Property#initializeName`, `Entity#isOrganizationEnabled`). `Entity#getImplementsStatement` adds `OrganizationEnabled` (boundary) to the interfaces of the entity's [generated class](#generated-class), and `OBDal#save(Object)`, through `OBDal#setClientOrganization`, fills a missing [organization](#organization) of an object that implements it with a [proxy](#proxy) of the current organization of `OBContext` (`Entity#getImplementsStatement`, `OBDal#setClientOrganization`). `SecurityChecker#checkWriteAccess(Object)`, through the private `SecurityChecker#checkWriteAccess(Object, boolean)` to which it delegates, takes the organization of such an object for its writable-organization test, and `OBInterceptor#checkReferencedOrganizations` returns at once for an object that does not implement the interface (`SecurityChecker#checkWriteAccess(Object)`, `SecurityChecker#checkWriteAccess(Object, boolean)`, `OBInterceptor#checkReferencedOrganizations`). While the `setFilterOnReadableOrganization(boolean)` switch is on, `OBCriteria#initialize` and `OBQuery#addOrgClientActiveFilter` restrict `organization.id` of an organization-enabled entity to the [readable organizations](#readable-organizations), unless the [organization is part of the key](#organization-part-of-key) (`OBCriteria#initialize`, `OBQuery#addOrgClientActiveFilter`). The separate `_ComputedColumns` class mapping of an entity with [computed columns](#computed-column) gets a read-only many-to-one for the organization when the entity is organization-enabled (`DalMappingGenerator#generateComputedColumnsClassMapping`).

Used in: [01-architecture](./01-architecture.md#per-entity-rules), [02-runtime-model](./02-runtime-model.md#flags), [03-dal-service-api](./03-dal-service-api.md#obdalsaveobject), [04-security-and-filtering](./04-security-and-filtering.md#client-organization-and-active-filtering)

### Parent link

A parent link is a property whose parent flag is set, so that `Property#isParent` is true: `Property#initializeFromColumn(Column, boolean)` copies the flag from the AD column, and `Entity#initialize(Table)` lists each property that it creates from a column and that carries the flag as a [parent property](#parent-property) of its entity, so the two terms name the same flag (`Property#initializeFromColumn(Column, boolean)`, `Entity#initialize(Table)`). When `ModelProvider#createChildProperty` adds a [child property](#child-property) to the referenced entity for a property of a child entity, it marks the new one-to-many property as a child, the flag that `Property#isChild` reads, only when that property is a parent link, and `DalMappingGenerator#generateOneToMany` gives a one-to-many property marked as a child `cascade="all,delete-orphan"` unless the owning or the target entity is a [view entity](#view-entity) (`ModelProvider#createChildProperty`, `DalMappingGenerator#generateOneToMany`). `ModelProvider#shouldGenerateChildPropertyInParent` accepts a property that references `Client`, `Organization`, `Module` or `Language` only when it is a parent link (`ModelProvider#shouldGenerateChildPropertyInParent`). `DalMappingGenerator#generateReferenceMapping` adds `cascade="persist"` to the mapping of a parent link that is mandatory (`DalMappingGenerator#generateReferenceMapping`).

Used in: [02-runtime-model](./02-runtime-model.md#how-the-runtime-model-is-built)

### Parent property

A parent property is a property of an entity that points to the entity's parent: `Entity#initialize(Table)` adds each property that it creates from a column and for which `Property#isParent` is true to the list that `Entity#getParentProperties` returns, and the Javadoc of that method describes the list as the properties pointing to the parent, which applies only when the entity is a child of another entity (`Entity#initialize(Table)`, `Entity#getParentProperties`). The flag is the one that makes a property a [parent link](#parent-link), and `Property#initializeFromColumn(Column, boolean)` copies it from the AD column (`Property#initializeFromColumn(Column, boolean)`). `Property#setTranslatable` makes a property translatable only when a parent property of the [translation entity](#translation-entity) references the first id property of the property's entity, and keeps that parent property as the [translation parent property](#translation-parent-property) (`Property#setTranslatable`). `DalUtil#copyToTarget(BaseOBObject, BaseOBObject, boolean, List)` copies no value into the id or the parent properties of the target, and its Javadoc states that they remain unchanged (`DalUtil#copyToTarget(BaseOBObject, BaseOBObject, boolean, List)`).

Used in: [02-runtime-model](./02-runtime-model.md#translatable-properties)

### Parent tree

The parent tree of an organization is the set of organization ids that `OrganizationStructureProvider#getNaturalTree(String)` obtains by calling the provider's `getParentTree` method, whose internals this documentation does not describe, with the organization id and `true`, and to which it adds the [child tree](#child-tree) to form the [natural tree](#natural-tree) (`OrganizationStructureProvider#getNaturalTree(String)`). `OrganizationStructureProvider#getNaturalTree(String)` makes that call only when the provider has a node for the organization, and otherwise returns a set that holds only the passed id (`OrganizationStructureProvider#getNaturalTree(String)`). Because `OBContext#setReadableOrganizations(Role)` unions the natural trees of the [active organizations](#active-organization) of the role unless they include `"0"`, the parent tree of each of those organizations is part of the [readable organizations](#readable-organizations) (`OBContext#setReadableOrganizations(Role)`).

Used in: [04-security-and-filtering](./04-security-and-filtering.md#readable-and-writable-sets)

### Pool

A pool is a named database connection pool for which the DAL keeps its own session and transaction: a `SessionHandler` holds one Hibernate [session](#session), one [transaction](#transaction) and an optional connection per pool name, and `SessionHandler#getSession(String)` treats a null name as the default pool `ExternalConnectionPool.DEFAULT_POOL` (boundary) (`SessionHandler#getSession(String)`). `OBDal#getInstance()` returns the instance for the default pool, `OBDal#getReadOnlyInstance()` the one for `ExternalConnectionPool.READONLY_POOL`, and `OBDal#getInstance(String)` the instance kept for a pool name, or the default instance when `DataPoolChecker` (boundary) reports that the default pool must be used (`OBDal#getInstance()`, `OBDal#getReadOnlyInstance()`, `OBDal#getInstance(String)`). An instance initializer of `SessionHandler`, a non-static block that runs each time a handler is created, assigns the static `externalConnectionPool` field from `ExternalConnectionPool.getInstance` (boundary) only when the `db.externalPoolClassName` setting is present and not empty, so a missing or empty setting leaves the field unassigned, and when that load fails it sets the field to null and logs the failure (instance initializer read by `SessionHandler#createSession(String)`). Only when that field is non-null and the pool has no stored connection does `SessionHandler#createSession(String)` take a connection from the [external connection pool](#external-connection-pool) through `SessionHandler#getNewConnection(String)`, store it for the pool and open the pool's session with it (`SessionHandler#createSession(String)`, `SessionHandler#getNewConnection(String)`). Otherwise `SessionHandler#createSession(String)` opens the session with the connection already stored for the pool, or, when none is stored, through `openSession()` of the [session factory](#session-factory), which is how a pool without a stored connection gets its session while the field is unassigned or null; the owning section is [01-architecture.md, External connection pool](./01-architecture.md#external-connection-pool) (`SessionHandler#createSession(String)`).

Used in: [01-architecture](./01-architecture.md#request-lifecycle), [03-dal-service-api](./03-dal-service-api.md#reading-guide)

### Positional parameter

A positional parameter is a `?` marker in a query clause whose value is bound by its position: for a non-null, non-empty list, `OBQuery#setParameters(List)` rewrites each `?` of the stored clause as the [named parameter](#named-parameter) `:__p0`, `:__p1` and so on, sets the value at that position, and fails when the clause holds more or fewer markers than the list holds values (`OBQuery#setParameters(List)`). Given a null or empty list, the method changes nothing (`OBQuery#setParameters(List)`). Its Javadoc gives the reason, that legacy-style query parameters are no longer supported in Hibernate, and names `setNamedParameters(Map)` as the replacement (`OBQuery#setParameters(List)`). The deprecated `OBDal#createQuery(Class, String, List)` hands its list to that method (`OBDal#createQuery(Class, String, List)`).

Used in: [03-dal-service-api](./03-dal-service-api.md#obdalcreatequeryclass-string-list)

### Primary key

A primary key is the column or set of columns that identifies the records of a table, and in the runtime model it is the id properties of an [entity](#entity): `Property#initializeFromColumn(Column, boolean)` takes a property's id flag from the key flag of its AD column, `Entity#initialize(Table)` adds every property with that flag to the entity's id properties, and the Javadoc of `Entity#getIdProperties` calls them the properties that make up the primary key of the entity (`Property#initializeFromColumn(Column, boolean)`, `Entity#initialize(Table)`, `Entity#getIdProperties`). `ModelProvider#removeInvalidTables` drops a table whose [data origin](#data-origin) is `Table` when it has no primary key columns, logging a warning, and keeps the tables of any other data origin (`ModelProvider#removeInvalidTables`). An entity with several id properties gets a [composite id](#composite-id), and an entity whose single id property is a reference, a [foreign key](#foreign-key), gets an extra [one-to-one](#one-to-one) [reference property](#reference-property) to the target entity (`ModelProvider#createCompositeId`, `ModelProvider#createIdReferenceProperty`). `DalMappingGenerator#generateMapping(Entity)` maps the primary key as a `<composite-id>` from `DalMappingGenerator#generateCompositeID` or as an `<id>` from `DalMappingGenerator#generateStandardID` (`DalMappingGenerator#generateMapping(Entity)`). The Javadoc of `Property#getReferencedProperty` says that a reference to the primary key of the referenced entity has no referenced property (`Property#getReferencedProperty`).

Used in: [02-runtime-model](./02-runtime-model.md#how-the-runtime-model-is-built)

### Primitive property

A primitive property is a property whose domain type is a `PrimitiveDomainType`: `Property#isPrimitive` reports it, and `Property#getPrimitiveType` then gives its Java type (`Property#isPrimitive`, `Property#getPrimitiveType`). `DalMappingGenerator#generatePrimitiveMapping` emits nothing for one whose Hibernate type is `Object`, maps booleans with Hibernate's `YesNoType`, uses a `formula` instead of a `column` when [SQL logic](#sql-logic) is set, adds `not-null="true"` when it is mandatory, and sets `update="false"` and `insert="false"` for [inactive properties](#inactive-property), properties of [view entities](#view-entity) and properties with SQL logic (`DalMappingGenerator#generatePrimitiveMapping`).

Used in: [01-architecture](./01-architecture.md#per-entity-rules), [02-runtime-model](./02-runtime-model.md#how-the-runtime-model-is-built)

### Projection

A projection is a Hibernate criteria setting that makes the query return computed values, such as a row count, in place of the queried objects (`OBCriteria#count()`). `OBCriteria#count()`, a convenience method that per its Javadoc the standard Hibernate criteria lacks, calls `OBCriteria#initialize`, sets Hibernate's `Projections.rowCount()` projection, reads the count through `OBCriteria#uniqueResult()` and resets the projection to null before it returns the count as an `int` (`OBCriteria#count()`).

Used in: [03-dal-service-api](./03-dal-service-api.md#obcriteriacount)

### Property

A property is the runtime-model object of class `Property` that models one attribute of an [entity](#entity); its Javadoc says a property can be a primitive type, a reference or a list (one-to-many) property (`Property#isPrimitive`, `Property#isOneToMany`). `Property#initializeFromColumn(Column)`, through `Property#initializeFromColumn(Column, boolean)`, copies from the AD column the key flag as id, the identifier and parent flags, the column name, the domain type, the default value, the [mandatory flag](#mandatory-flag) and the other column settings, and `Property#initializeName` gives it its name (`Property#initializeFromColumn(Column, boolean)`, `Property#initializeName`). `Entity#getProperties` lists the properties of an entity, and `Property#getIndexInEntity` gives a property's position in that list, which indexes the value array of `BaseOBObject` (`Entity#getProperties`, `Property#getIndexInEntity`). The mandatory flag is copied from the column and then overwritten by `ModelProvider#initialize` from the database not-null value, except for the entities and properties that 02 lists (`ModelProvider#initialize`).

Used in: [01-architecture](./01-architecture.md#layers), [02-runtime-model](./02-runtime-model.md#reading-guide), [03-dal-service-api](./03-dal-service-api.md#obdalfinduniqueconstrainedobjectsbaseobobject), [04-security-and-filtering](./04-security-and-filtering.md#access-checks)

### Property path

A property path is a text of dot-separated property names read from a starting entity, which the Javadoc of `DalUtil#getPropertyFromPath` calls a so-called property path (`DalUtil#getPropertyFromPath`). `DalUtil#getPropertyFromPath(Entity, String)` and `DalUtil#getValueFromPath(BaseOBObject, String)` both treat `$` as a dot and stop at a part named `_identifier`, for which they return the first identifier property of the current entity or the [identifier](#identifier) of the current object (`DalUtil#getPropertyFromPath`, `DalUtil#getValueFromPath`). `DalUtil#getPropertyFromPath` walks from entity to entity through the target entity of each property and returns the last property reached, or null for an unknown part or for an `_identifier` part of an entity without identifier properties (`DalUtil#getPropertyFromPath`). `DalUtil#getValueFromPath` returns null for a null object and otherwise walks the values of a [business object](#business-object), read with `BaseOBObject#get(String)`, returning the first value that is not a `BaseOBObject` or else the last object reached; when the current entity has no property for a part, it calls itself with the text of the path that follows that part on the same object, or returns null when the whole path is that one part (`DalUtil#getValueFromPath`). The Javadoc of `DalUtil#getValueFromPath` repeats the description of `DalUtil#getPropertyFromPath`, saying that the path results in a property being returned, while its `@return` text and its body give a value; 02 records this as an ambiguity that it does not resolve (`DalUtil#getValueFromPath`).

Used in: [02-runtime-model](./02-runtime-model.md#dalutil)

### Property-name constant

A property-name constant is a static constant of the generated entity class against which `Property#initializeName` corrects the name of a property: when the property has no name yet, the method takes one from `NamingUtil` (boundary), then passes the [mapping class](#mapping-class) that `Entity#getMappingClass` returns and the name to `NamingUtil` (boundary), sets the result as the property name, and registers the property under that name with `Entity#addPropertyByName` (`Property#initializeName`). Its source comment describes this step as correcting the name with the static constant in the generated entity class (`Property#initializeName`). The [audit properties](#audit-properties) and the client-enabled, organization-enabled, active-enabled and [inherited access](#inherited-access) flags that `Property#initializeName` sets afterwards are derived from the corrected name, and `ModelProvider#initialize` calls the method for the properties that are not one-to-many and, after it has created the [child properties](#child-property), for the one-to-many properties (`Property#initializeName`, `ModelProvider#initialize`). Which constants a generated class declares cannot be determined from the repository, because the generated sources are Not Found (`GenerateEntitiesTask#execute`).

Used in: [02-runtime-model](./02-runtime-model.md#naming-rules)

### Property-ref

A property-ref is the attribute of a Hibernate reference mapping that names the target property when the reference does not point to the target's id: `DalMappingGenerator#generateReferenceMapping` adds it to [one-to-one](#one-to-one) and [many-to-one](#many-to-one) mappings when the referenced property is not the target's id (`DalMappingGenerator#generateReferenceMapping`). `Property#setReferencedProperty` records the referenced property of a [reference property](#reference-property) and sets the target entity to that property's entity (`Property#setReferencedProperty`).

Used in: [01-architecture](./01-architecture.md#per-entity-rules)

### Provider configuration

Provider configuration is configuration for `OBProvider`, the DAL [service locator](#service-locator), supplied as a stream or a file: the protected `OBProvider#register(String, InputStream)` and `OBProvider#register(String, String)` each create an `OBProviderConfigReader` (boundary) and hand it a prefix together with the stream or the configuration file name, and their source comments mark both as used by `OBConfigFileProvider` (boundary) (`OBProvider#register(String, InputStream)`, `OBProvider#register(String, String)`). `OBProvider#CONFIG_FILE_NAME` holds the configuration file name `provider-config.xml`, and neither registration method reads it: `OBProvider#register(String, InputStream)` receives the configuration as a stream and `OBProvider#register(String, String)` receives the file name as its `configFile` argument (`OBProvider#CONFIG_FILE_NAME`, `OBProvider#register(String, InputStream)`, `OBProvider#register(String, String)`).

Used in: [03-dal-service-api](./03-dal-service-api.md#obproviderconfig_file_name)

### Provider registration

A provider registration is an entry that `OBProvider` keeps under a class name or service name, recording the implementation class to instantiate, whether its instance is a [singleton](#singleton) and whether the registration can be overwritten (`OBProvider#register(String, Class, boolean)`). `OBProvider#register(Class, Class, boolean)` registers `instanceClass` as the implementation of the Openbravo class `registrationClass`, and per its Javadoc overwrites a current registration only when `overwrite` is true; it is the extension point for supplying a different implementation of an Openbravo class (`OBProvider#register(Class, Class, boolean)`). A registration created with `overwrite` true is itself not overwritable, and the source comment gives the reason: a registration which overwrites others is not overwritable (`OBProvider#register(String, Class, boolean)`). `OBProvider#get(Class)` returns the instance of the registration for a class, registering the class as its own implementation first when no registration exists (`OBProvider#get(Class)`). `OBProvider#registerInstance(Class, Object, boolean)` sets a fixed instance on a registration: it calls `OBProvider#register(String, Class, boolean)` and then sets the supplied instance on whichever registration is stored under the class name, so a registration that this call keeps also receives the instance, while its Javadoc says that with `overwrite` false a current registration is not overwritten; [03-dal-service-api.md, OBProvider#registerInstance(Class, Object, boolean)](./03-dal-service-api.md#obproviderregisterinstanceclass-object-boolean) records this as an ambiguity that these docs do not resolve (`OBProvider#registerInstance(Class, Object, boolean)`, `OBProvider#register(String, Class, boolean)`).

Used in: [03-dal-service-api](./03-dal-service-api.md#reading-guide)

### Proxy

A proxy is a Hibernate placeholder for an object that is not loaded yet: `OBDal#getProxy(String, Object)` returns the result of `internalLoad` with no read-access check and no existence check, its Javadoc promises a non-loaded Hibernate proxy only for an object that Hibernate has not already loaded, and the same Javadoc states that a missing row is detected only when a referencing object is persisted or the proxy is initialized (`OBDal#getProxy(String, Object)`). The `@return` tag of that Javadoc says the method returns "the object, or null if none found", while the same Javadoc says the method does not check whether the object exists, and [03-dal-service-api.md, OBDal#getProxy(String, Object)](./03-dal-service-api.md#obdalgetproxystring-object) records this as an ambiguity that these docs do not resolve (`OBDal#getProxy(String, Object)`). `OBDal#save(Object)` fills a missing client or organization with proxies of the current ones, and `OBInterceptor#onNew` sets the audit users, the client and the organization to proxies obtained through `OBDal#getProxy(Class, String)` (`OBDal#setClientOrganization`, `OBInterceptor#onNew`). The deprecated `DalUtil#getId(Object)` reads the id held by a Hibernate proxy without loading the object (`DalUtil#getId(Object)`). `DalUtil#getEntityName(Object)`, which is not deprecated, reads the entity name through the persistent class of a Hibernate proxy without loading the object (`DalUtil#getEntityName(Object)`). In the runtime model the word also names the `_computedColumns` property, which `Property#isProxy` marks and whose [mandatory flag](#mandatory-flag) `ModelProvider#initialize` does not log as missing (`Property#isProxy`, `ModelProvider#initialize`).

Used in: [02-runtime-model](./02-runtime-model.md#how-the-runtime-model-is-built), [03-dal-service-api](./03-dal-service-api.md#obdalsaveobject), [04-security-and-filtering](./04-security-and-filtering.md#shared-event-handling)

### Query profile

A query profile is the `String` value that the DAL passes to `QueryTimeOutUtil` (boundary) to set a [query timeout](#query-timeout): `OBCriteria#initialize` takes it from `SessionInfo` (boundary) and sets the timeout only when that profile is not null (`OBCriteria#initialize`). For an `OBQuery`, the private `OBQuery#addQueryProfile` uses the [query type](#query-type) as the profile when one is set and the `SessionInfo` query profile otherwise, and sets no timeout when both are null; `OBQuery#createQuery(Class)` and `OBQuery#getRowNumber(String)` call it on the query they create (`OBQuery#addQueryProfile`, `OBQuery#createQuery(Class)`, `OBQuery#getRowNumber(String)`). The DAL code checks the profile only for null and passes it on unchanged (`OBCriteria#initialize`, `OBQuery#addQueryProfile`).

Used in: [03-dal-service-api](./03-dal-service-api.md#obcriteria)

### Query timeout

A query timeout is a time limit on a database query, which the DAL sets through `QueryTimeOutUtil` (boundary) for a [query profile](#query-profile): `OBCriteria#initialize`, which the executing methods of `OBCriteria` call first, sets one on the criteria when `SessionInfo` (boundary) holds a query profile (`OBCriteria#initialize`). `OBQuery#createQuery(Class)` and `OBQuery#getRowNumber(String)` set one on the Hibernate query they create, for the [query type](#query-type) of the `OBQuery` when it is not null and for the `SessionInfo` query profile otherwise (`OBQuery#addQueryProfile`, `OBQuery#createQuery(Class)`, `OBQuery#getRowNumber(String)`). `OBQuery#count()` sets none (`OBQuery#count()`).

Used in: [03-dal-service-api](./03-dal-service-api.md#obcriteria)

### Query type

A query type is a `String` that an `OBQuery` holds and that its Javadoc calls the type of the underlying query: `OBQuery#setQueryType(String)` stores it and returns the query, and `OBQuery#getQueryType()` returns it, null until one is set (`OBQuery#setQueryType(String)`, `OBQuery#getQueryType()`). When it is not null, `OBQuery#createQuery(Class)` and `OBQuery#getRowNumber(String)` pass it to `QueryTimeOutUtil` (boundary) to set the [query timeout](#query-timeout), in place of the `SessionInfo` (boundary) [query profile](#query-profile) (`OBQuery#addQueryProfile`, `OBQuery#createQuery(Class)`). `OBQuery#count()` does not apply it (`OBQuery#count()`).

Used in: [03-dal-service-api](./03-dal-service-api.md#obquerycount)

### Readable clients

The readable clients are the client ids to which `OBCriteria` and `OBQuery` restrict queries on [client-enabled entities](#client-enabled-entity): `OBContext#setReadableClients(Role)` sets them to `{"0"}` when the [user level](#user-level) is `S` or the client of the role is `"0"`, and otherwise to the client of the role plus `"0"` (`OBContext#setReadableClients(Role)`). `OBContext#getReadableClients()` computes the array when none is cached and returns a copy (`OBContext#getReadableClients()`). With the client switch on, `OBCriteria#initialize` restricts `client.id` to them, and `OBQuery#addOrgClientActiveFilter` records them as the [named parameter](#named-parameter) `_dal_readableClients_dal_` through `OBQuery#setNamedParameter(String, Object)`, which `OBQuery#setParameters(Query)` binds when the Hibernate query is created (`OBCriteria#initialize`, `OBQuery#addOrgClientActiveFilter`, `OBQuery#setNamedParameter(String, Object)`, `OBQuery#setParameters(Query)`). The deprecated `OBDal#getReadableClientsInClause()` returns them as an HQL in-clause (`OBDal#getReadableClientsInClause()`).

Used in: [03-dal-service-api](./03-dal-service-api.md#obdalgetreadableclientsinclause), [04-security-and-filtering](./04-security-and-filtering.md#reading-guide)

### Readable organizations

The readable organizations are the organization ids to which `OBCriteria` and `OBQuery` restrict queries on [organization-enabled entities](#organization-enabled-entity): `OBContext#setReadableOrganizations(Role)` computes them as every organization of the current client when the [active organizations](#active-organization) of the role include `"0"`, and otherwise as the union of the [natural trees](#natural-tree) of those organizations, and always adds `"0"` (`OBContext#setReadableOrganizations(Role)`). With the organization switch on, `OBCriteria#initialize` restricts `organization.id`, or `id.organization.id` when the organization is part of the key, to them, and `OBQuery#addOrgClientActiveFilter` records them as the [named parameter](#named-parameter) `_dal_readableOrganizations_dal_` through `OBQuery#setNamedParameter(String, Object)`, which `OBQuery#setParameters(Query)` binds when the Hibernate query is created (`OBCriteria#initialize`, `OBQuery#addOrgClientActiveFilter`, `OBQuery#setNamedParameter(String, Object)`, `OBQuery#setParameters(Query)`). `OBContext#getReadableOrganizations()` computes them when none are cached, which is the case on first use and after `OBContext#setRole(Role)` or `OBContext#addWritableOrganization(String)` has cleared them, and returns a copy (`OBContext#getReadableOrganizations()`). `OBContext#setRole(Role)` does not clear the cached `organizationList` field in which the `"0"` branch of `OBContext#setReadableOrganizations(Role)` stores every organization of the current client through `OBContext#getOrganizations(Client)`, and `OBContext#getOrganizationList(Role, List, Set, boolean)` returns a copy of that field whenever it is set, so a recomputation after a role change can start from that client-wide list without reading the role-organization assignments of the new role (`OBContext#setRole(Role)`, `OBContext#getOrganizationList(Role, List, Set, boolean)`). [04-security-and-filtering.md, Readable and writable sets](./04-security-and-filtering.md#readable-and-writable-sets) records this reuse as an ambiguity that it does not resolve (`OBContext#setReadableOrganizations(Role)`). The deprecated `OBDal#getReadableOrganizationsInClause()` returns them as an HQL in-clause (`OBDal#getReadableOrganizationsInClause()`).

Used in: [03-dal-service-api](./03-dal-service-api.md#obdalgetreadableorganizationsinclause), [04-security-and-filtering](./04-security-and-filtering.md#reading-guide)

### Real property

A real property is a property that `Entity#getRealProperties(boolean)` returns: any property of the entity except the `_computedColumns` [proxy](#proxy) property and the properties whose reference id is `Entity#SEARCH_VECTOR_REF_ID`, with [computed columns](#computed-column) left out unless the argument is `true` (`Entity#getRealProperties`). The Javadoc of `Entity#getRealProperties(boolean)` describes the flag the other way round, saying that computed columns are excluded when it is `true`; 02 records this as an ambiguity and does not resolve it (`Entity#getRealProperties`).

Used in: [02-runtime-model](./02-runtime-model.md#validation-and-real-properties)

### Reference implementation class

A reference implementation class is a class named as the implementation of an AD reference: `ModelProvider#initializeReferenceClasses` reads the distinct reference implementation class names through a plain JDBC connection, before `ModelProvider#initialize` opens the session on the [model session factory](#model-session-factory), and loads each class (`ModelProvider#initializeReferenceClasses`, `ModelProvider#initialize`). For each class assignable to `BaseDomainType` (boundary), it creates an instance and passes every class returned by that instance's `getClasses()` to `ModelSessionFactoryController#addAdditionalClasses`, so the implementation class itself is registered only when its own `getClasses()` returns it; any failure is rethrown as `OBException` with the message "Failed to load reference classes" (`ModelProvider#initializeReferenceClasses`). `BaseDomainType` and the other [domain type](#domain-type) classes are boundary classes (`ModelProvider#initializeReferenceClasses`).

Used in: [02-runtime-model](./02-runtime-model.md#how-the-runtime-model-is-built)

### Reference property

A reference property is a property whose value is an object of another entity: for each non-primitive column, `ModelProvider#setReferencedPropertiesForTable` links the column's property to the property of the referenced column through `Property#setReferencedProperty`, which also sets the target entity and flags the referenced property as being referenced (`ModelProvider#setReferencedPropertiesForTable`, `Property#setReferencedProperty`). `ModelProvider#setReferenceProperties` runs that pass for the tables of the model, and `ModelProvider#setVirtualPropertiesForReferenceId` adds a [one-to-one](#one-to-one) reference property for an id that is a reference (`ModelProvider#setReferenceProperties`, `ModelProvider#setVirtualPropertiesForReferenceId`). `DalMappingGenerator#generateReferenceMapping` maps it as a one-to-one or a [many-to-one](#many-to-one) (`DalMappingGenerator#generateReferenceMapping`).

Used in: [01-architecture](./01-architecture.md#per-entity-rules), [02-runtime-model](./02-runtime-model.md#how-the-runtime-model-is-built)

### Role

A role is the record under which the [user context](#user-context) computes its access: `OBContext#initialize(String, String, String, String, String, String)` takes the passed role id, otherwise the default role of the user when that role is active, otherwise the first active [user-role assignment](#user-role-assignment) with an active role, and throws `OBSecurityException` when there is none (`OBContext#initialize(String, String, String, String, String, String)`). `OBContext#setRole(Role)` marks the context as administrator when the role id is `"0"`, takes the [user level](#user-level) from the role, and clears the cached `EntityAccessChecker`, readable clients, readable organizations, writable organizations and deactivated organizations, but not the cached `organizationList` field from which the readable and writable organizations are computed (`OBContext#setRole(Role)`, `OBContext#getOrganizationList(Role, List, Set, boolean)`). Once the `"0"` branch of `OBContext#setReadableOrganizations(Role)` has stored every organization of the current client in that field through `OBContext#getOrganizations(Client)`, and until `OBContext#addWritableOrganization(String)` clears the field, `OBContext#getOrganizationList(Role, List, Set, boolean)` returns a copy of it without reading the role-organization assignments of the new role, and [04-security-and-filtering.md, Readable and writable sets](./04-security-and-filtering.md#readable-and-writable-sets) records this reuse as an ambiguity that it does not resolve (`OBContext#getOrganizationList(Role, List, Set, boolean)`, `OBContext#getOrganizations(Client)`). The role determines the [readable clients](#readable-clients), the [readable organizations](#readable-organizations), the [writable organizations](#writable-organizations) and, through `OBContext#getEntityAccessChecker`, the [entity access](#entity-access) of the context (`OBContext#setReadableClients(Role)`, `OBContext#getEntityAccessChecker`). Role `"0"` puts the context in admin mode and switches the [org/client access check](#orgclient-access-check) off whatever the admin mode stack holds (`OBContext#isInAdministratorMode()`, `OBContext#doOrgClientAccessCheck()`).

Used in: [04-security-and-filtering](./04-security-and-filtering.md#reading-guide)

### Role-organization assignment

A role-organization assignment is a record that links a [role](#role) to an [organization](#organization) and has an active flag of its own, separate from that of the organization (`OBContext#initialize(String, String, String, String, String, String)`). When no organization id is passed, the user has no active default organization and the role is not an [automatic role](#automatic-role), `OBContext#initialize(String, String, String, String, String, String)` takes the organization of the first active assignment of the role whose organization is active, ordered by organization id descending, and takes the client of that assignment when no client id was passed (`OBContext#initialize(String, String, String, String, String, String)`). The [active organizations](#active-organization) of a role include the organizations of its active assignments whose organization is active, and its [deactivated organizations](#deactivated-organization) include the organizations of its active assignments whose organization is inactive (`OBContext#getOrganizationList(Role, List, Set, boolean)`, `OBContext#getDeactivatedOrganizations()`).

Used in: [04-security-and-filtering](./04-security-and-filtering.md#initialization-order)

### Runtime model

The runtime model is the in-memory list of `Entity` objects, each with its `Property` objects, that `ModelProvider#getModel` returns and that the Hibernate mapping, the entity generator and the DAL services read (`ModelProvider#getModel`, `DalMappingGenerator#generateMapping()`, `GenerateEntitiesTask#execute`). `ModelProvider#initialize` builds it from the [Application Dictionary](#application-dictionary-ad), and the lookups `ModelProvider#getEntity(String)`, `ModelProvider#getEntity(Class)`, `ModelProvider#getEntityByTableName` and `ModelProvider#getEntityByTableId` read the indexes it fills (`ModelProvider#initialize`). `ModelProvider#getEntity(String)` throws `CheckException` with "not found in runtime model" for an unknown entity name (`ModelProvider#getEntity(String)`).

- Code qualification: it is built lazily on the first `ModelProvider#getModel()` call and rebuilt by `ModelProvider#refresh()`, which replaces the registered `ModelProvider` with a new instance and builds its model (`ModelProvider#getModel`, `ModelProvider#refresh`). It is also built at [development time](#development-time) by `GenerateEntitiesTask#execute`, which calls `ModelProvider#getModel` (`GenerateEntitiesTask#execute`). Its [mandatory flags](#mandatory-flag) come from the database not-null metadata that `ModelProvider#getColumnMandatories` reads, not only from the AD column flag (`ModelProvider#getColumnMandatories`, `ModelProvider#initialize`).

Used in: [01-architecture](./01-architecture.md#reading-guide), [02-runtime-model](./02-runtime-model.md#reading-guide), [03-dal-service-api](./03-dal-service-api.md#obdal-creating-queries)

### Search-vector reference

The search-vector reference is the AD reference whose id is the constant `Entity.SEARCH_VECTOR_REF_ID`, `81FCDA657A5540F69B0AE57B4E0F8A51`: `DalMappingGenerator#generateMapping(Entity)` emits no mapping for a property whose [domain type](#domain-type) has that reference (`DalMappingGenerator#generateMapping(Entity)`). `Entity#getRealProperties(boolean)` also leaves such properties out of the list it returns, whatever its argument, while `Entity#initialize(Table)` creates them from their columns like any other property, so `Entity#getProperties` lists them (`Entity#getRealProperties`, `Entity#initialize(Table)`).

Used in: [01-architecture](./01-architecture.md#which-entities-are-mapped)

### Select clause

The select clause is the part of an [HQL](#hql) query that names what the query returns: `OBQuery#setSelectClause(String)` stores one and returns the query, and `OBQuery#getSelectClause()` returns it, null until one is set (`OBQuery#setSelectClause(String)`, `OBQuery#getSelectClause()`). When a select clause is set, `OBQuery#createQueryString` starts the query string with `select` and that clause, in place of the [alias](#alias) when the caller's clause starts with one; otherwise it starts with `select` and the alias, or with `from` when there is no alias (`OBQuery#createQueryString`). The Javadoc of `OBQuery#setSelectClause(String)` warns that the clause can change the type of the objects the query returns, and the Javadoc of `OBQuery#createQuery(Class)` states that a select clause takes precedence over `clz` for that type (`OBQuery#setSelectClause(String)`, `OBQuery#createQuery(Class)`). `OBQuery#uniqueResultObject()` returns its single result as `Object`, so the result is not typed to the queried entity (`OBQuery#uniqueResultObject()`).

Used in: [03-dal-service-api](./03-dal-service-api.md#obquerygetrownumberstring)

### Service locator

A service locator is a registry that callers ask for the instances they use: the `OBProvider` class Javadoc states that `OBProvider` provides the runtime instances of model entities as well as service instances, describes it as an implementation of the service locator pattern, and says that classes are registered by their class type, each identified as a [singleton](#singleton) or not (`OBProvider#register(String, Class, boolean)`). `OBProvider#get(Class)` returns the instance of the [provider registration](#provider-registration) for a class, registering the class as its own implementation first when no registration exists, and `OBDal#getInstance()` obtains its instance through it (`OBProvider#get(Class)`, `OBDal#getInstance()`).

Used in: [03-dal-service-api](./03-dal-service-api.md#obprovider)

### Session

A session is a Hibernate session, through which the DAL loads and saves objects: `SessionHandler#getSession(String)` returns the session that the thread's [session handler](#session-handler) holds for a [pool](#pool), and begins a session and a [transaction](#transaction) on first use (`SessionHandler#getSession(String)`). `SessionHandler#begin(String)` creates it with the [flush mode](#flush-mode) `FlushMode.COMMIT`, and `SessionHandler#createSession(String)` opens it from the session factory of `SessionFactoryController` (boundary) (`SessionHandler#begin(String)`, `SessionHandler#createSession(String)`). `OBDal#getSession()` returns the session of the instance's pool, and `SessionHandler#commitAndClose(String)` and `SessionHandler#rollback(String)` close it after their commit or rollback attempt, except that `SessionHandler#rollback(String)` leaves it open when checking or closing the pool's connection during its cleanup throws an `SQLException` (`OBDal#getSession()`, `SessionHandler#commitAndClose(String)`, `SessionHandler#rollback(String)`). The session that `ModelProvider#initialize` opens on the [model session factory](#model-session-factory) is separate and read-only (`ModelProvider#initialize`, `ModelSessionFactoryController#setInterceptor`).

Used in: [01-architecture](./01-architecture.md#reading-guide), [02-runtime-model](./02-runtime-model.md#how-the-runtime-model-is-built), [03-dal-service-api](./03-dal-service-api.md#reading-guide), [04-security-and-filtering](./04-security-and-filtering.md#reading-guide)

### Session factory

A session factory is the Hibernate object that opens sessions: `DalSessionFactory` delegates to the Hibernate session factory passed to `DalSessionFactory#setDelegateSessionFactory`, and `DalSessionFactory#openSession()` initializes the database [session info](#session-info) on the connection of the session that the delegate opens (`DalSessionFactory#setDelegateSessionFactory`, `DalSessionFactory#openSession()`). Its class Javadoc gives the reason for the wrapper: every call is delegated to the real session factory except the calls that open a session, for which an extra action sets session information in the database; the Javadoc of `DalSessionFactory#getDelegateSessionFactory` adds that normal application code must use `DalSessionFactory` (`DalSessionFactory#openSession()`, `DalSessionFactory#getDelegateSessionFactory`). The open methods call the delegate first and then initialize session info on the connection of the session it returns, while the class Javadoc describes the opposite order; [01-architecture.md, Startup sequence](./01-architecture.md#startup-sequence) records this as an ambiguity that it does not resolve (`DalSessionFactory#openSession()`, `DalSessionFactory#openStatelessSession()`, `DalSessionFactory#openStatelessSession(Connection)`). The `DalSessionFactoryController` class Javadoc describes that controller as the class that initializes and provides the session factory of the runtime DAL, and `DalSessionFactoryController#setInterceptor` installs `OBInterceptor` on its configuration (`DalSessionFactoryController#mapModel`, `DalSessionFactoryController#setInterceptor`). The Application Dictionary is read through a separate [model session factory](#model-session-factory) (`ModelProvider#initialize`).

Used in: [01-architecture](./01-architecture.md#reading-guide), [02-runtime-model](./02-runtime-model.md#how-the-runtime-model-is-built)

### Session handler

The session handler is the `SessionHandler` of the current thread, which keeps one Hibernate session, one transaction and an optional connection per [pool](#pool): `SessionHandler#getInstance` returns the handler stored in a thread-local and, when the thread has none, creates one through `OBProvider#get(Class)` (`SessionHandler#getInstance`). `SessionHandler#deleteSessionHandler` removes it from the thread-local, so the next `SessionHandler#getInstance` creates a new one, and `SessionHandler#isSessionHandlerPresent(String)` tells whether the thread has a handler available for a pool (`SessionHandler#deleteSessionHandler`, `SessionHandler#isSessionHandlerPresent(String)`). `OBDal#commitAndClose()` and `OBDal#rollbackAndClose()` act only when that method returns true for their pool (`OBDal#commitAndClose()`, `OBDal#rollbackAndClose()`).

Used in: [01-architecture](./01-architecture.md#request-lifecycle)

### Session info

Session info is the user session information that the DAL sets in the database on a connection: `DalSessionFactory#openSession()` calls `DalSessionFactory#initConnection`, which initializes it and then runs the statement configured in the `bbdd.sessionConfig` setting, while `DalSessionFactory#openStatelessSession()` and `DalSessionFactory#openStatelessSession(Connection)` only initialize it (`DalSessionFactory#openSession()`, `DalSessionFactory#openStatelessSession()`). No source states whether that difference is intended, and 01 records it as an ambiguity (`DalSessionFactory#openSession()`). In the `finally` block of its end-of-request hook, `DalRequestFilter#doFilter` calls `SessionInfo.init()` (boundary), which its source comment describes as setting all session info to null (`DalRequestFilter#doFilter`). `OBDal#flush()` passes its connection to `SessionInfo.saveContextInfoIntoDB` (boundary) before it flushes a dirty session (`OBDal#flush()`).

Used in: [01-architecture](./01-architecture.md#startup-sequence)

### Session-in-view

Session-in-view is the pattern that the Javadoc of `SessionHandler#doSessionInViewPatter` defines as closing and committing the session at the end of the request, and the method always returns true (`SessionHandler#doSessionInViewPatter`). The `DalRequestFilter` class Javadoc states that each request is handled within a transaction that is committed or rolled back at the end of the request (`DalRequestFilter#doFilter`).

Used in: [01-architecture](./01-architecture.md#session-in-view)

### Singleton

A singleton is a class of which one shared instance is used: `OBProvider#register(String, Class, boolean)` makes a [provider registration](#provider-registration) a singleton when the instance class implements `OBSingleton` (boundary), and the Javadoc of `OBProvider#removeInstance(Class)` describes the singleton instance of a class as held in the internal registry and recreated at the next request after its removal (`OBProvider#register(String, Class, boolean)`, `OBProvider#removeInstance(Class)`). The `OBProvider` class Javadoc describes it as an implementation of the [service locator](#service-locator) pattern in which each registered class is treated as a singleton or not (`OBProvider#register(String, Class, boolean)`). `OBDal` implements `OBNotSingleton`, whose Javadoc nevertheless reads "Tags a class as being a singleton", and `OBDal#getInstance()` lazily keeps the instance it obtains from `OBProvider#get(Class)` in a static field whenever that field is null; 02 records this as an ambiguity (`OBDal#getInstance()`, `OBProvider#register(String, Class, boolean)`). The null check in `OBDal#getInstance()` is not synchronized, so the code makes no exactly-once or thread-safety promise for that instance (`OBDal#getInstance()`).

Used in: [02-runtime-model](./02-runtime-model.md#implemented-interfaces), [03-dal-service-api](./03-dal-service-api.md#obprovider)

### SQL function

An SQL function is an entry of the map of `SQLFunction` objects that `DalSessionFactoryController#getSQLFunctions` returns: the method merges the maps returned by every injected `SQLFunctionRegister` (boundary), skips registers that return null, and caches the merged map for later calls (`DalSessionFactoryController#getSQLFunctions`). `DalSessionFactoryController` declares this method as an override of a method of its boundary superclass `SessionFactoryController`, and the in-scope source does not establish which code calls it or when (`DalSessionFactoryController#getSQLFunctions`).

Used in: [01-architecture](./01-architecture.md#registering-the-mapping)

### SQL logic

SQL logic is the SQL expression that the mapping of a property uses in place of a database column: `Property#initializeFromColumn(Column, boolean)` copies it from the AD column, `Property#getSqlLogic` returns it, and `Property#isComputedColumn` is true when it is set, which makes the property a [computed column](#computed-column) that, per the Javadoc of `Property#isComputedColumn`, is calculated from an SQL formula and accessed through a [proxy](#proxy) (`Property#initializeFromColumn(Column, boolean)`, `Property#isComputedColumn`). `DalMappingGenerator#generateMapping(Entity)` collects every property that is not one-to-many and has SQL logic instead of mapping it in the entity's class, and `DalMappingGenerator#generateComputedColumnsClassMapping` maps those properties by the primitive and reference rules (`DalMappingGenerator#generateMapping(Entity)`, `DalMappingGenerator#generateComputedColumnsClassMapping`). Under those rules `DalMappingGenerator#generatePrimitiveMapping` and `DalMappingGenerator#generateReferenceMapping` write a `formula` built from the SQL logic instead of a `column`, and `DalMappingGenerator#generatePrimitiveMapping` also sets `update="false"` and `insert="false"` (`DalMappingGenerator#generatePrimitiveMapping`, `DalMappingGenerator#generateReferenceMapping`). `ModelProvider#shouldGenerateChildPropertyInParent` rejects a property with SQL logic, so no [child property](#child-property) is created for it (`ModelProvider#shouldGenerateChildPropertyInParent`).

Used in: [01-architecture](./01-architecture.md#per-entity-rules), [02-runtime-model](./02-runtime-model.md#how-the-runtime-model-is-built)

### src-gen

`src-gen` is the source folder, set by the `base.src.gen` property of `build.xml`, into which `GenerateEntitiesTask#execute` writes the [generated classes](#generated-class): a UTF-8 file at `src-gen/<package path>/<Class>.java` for each entity that is neither datasource-based, HQL-based nor virtual, plus a `<SimpleClassName>_ComputedColumns.java` file in the same package directory for each entity that is neither datasource-based nor HQL-based and has [computed columns](#computed-column), written only when `GenerateEntitiesTask#hasChanged` returns true (`GenerateEntitiesTask#execute`). `src/build.xml#clean.src.gen` deletes its contents except files matching `**/.keep`, and `GenerateEntitiesTask#hasChanged` is true when `src-gen/org/openbravo/model/ad` does not exist (`src/build.xml#clean.src.gen`, `GenerateEntitiesTask#hasChanged`). In the repository the folder holds only the empty `src-gen/.keep`, so no generated class is available, and `SystemInformation` is recorded as Not Found (`GenerateEntitiesTask#execute`).

Used in: [01-architecture](./01-architecture.md#entity-generation-generateentities), [02-runtime-model](./02-runtime-model.md#worked-example-systeminformation)

### Stateless session

A stateless session is a Hibernate session that `DalSessionFactory#openStatelessSession()` or `DalSessionFactory#openStatelessSession(Connection)` opens; both carry the Javadoc sentence that they set user session information in the database, but only initialize [session info](#session-info) and do not run the `bbdd.sessionConfig` statement that `DalSessionFactory#openSession()` runs (`DalSessionFactory#openStatelessSession()`). No source states whether the difference is intended, and 01 records it as an ambiguity that it does not resolve (`DalSessionFactory#openSession()`).

Used in: [01-architecture](./01-architecture.md#startup-sequence)

### System language

A system language is a language record whose system-language flag is set: while it resolves a context, `OBContext#initialize(String, String, String, String, String, String)` counts these records and records that translations are installed when more than one exists, and its source comment states that there is always at least one, the base language (`OBContext#initialize(String, String, String, String, String, String)`). `OBContext#hasTranslationInstalled` returns that flag for the context of the thread, or false when no context is set, and `BaseOBObject#get(String, Language, String)` looks for a translation of a [translatable property](#translatable-property) only while it is true (`OBContext#hasTranslationInstalled`, `BaseOBObject#get(String, Language, String)`).

Used in: [04-security-and-filtering](./04-security-and-filtering.md#initialization-order)

### Table-based entity

A table-based entity is an [entity](#entity) whose AD `Table` record has the [data origin](#data-origin) `Table`, the value that `ModelProvider#initialize` and `ModelProvider#removeInvalidTables` test for, so that `Entity#initialize(Table)` marks it neither as a [datasource-based entity](#datasource-based-entity) nor as an [HQL-based entity](#hql-based-entity) (`ModelProvider#initialize`, `Entity#initialize(Table)`). `ModelProvider#removeInvalidTables` drops such a table when it has no [primary key](#primary-key) columns, logging a warning, while it keeps every table of another data origin (`ModelProvider#removeInvalidTables`). `ModelProvider#initialize` indexes only table-based tables, and their entities, by table name, so `ModelProvider#getEntityByTableName` finds only table-based entities, and `ModelProvider#getTable` and `ModelProvider#getTableWithoutCheck` find only table-based tables (`ModelProvider#initialize`, `ModelProvider#getEntityByTableName`, `ModelProvider#getTable`). `ModelProvider#buildUniqueConstraints` skips a [unique constraint](#unique-constraint) whose table has no table-based entity (`ModelProvider#buildUniqueConstraints`).

Used in: [02-runtime-model](./02-runtime-model.md#how-the-runtime-model-is-built)

### Thread handler

A thread handler is a `DalThreadHandler` (boundary), inside which `DalRequestFilter#doFilter` runs each request: it creates an anonymous subclass that overrides the hooks `doBefore`, `doAction` and `doFinal`, and calls its `run()` (`DalRequestFilter#doFilter`). The `DalRequestFilter` class Javadoc gives the reason: handling the request thread inside a `DalThreadHandler` ensures that every request is handled within a transaction that is committed or rolled back at the end of the request (`DalRequestFilter#doFilter`). The Javadoc of `SessionHandler#setDoRollback(boolean)` says the `DalThreadHandler` uses the rollback request it records, while which cleanup calls the handler makes, and in what order, is not shown by any in-scope code (`SessionHandler#setDoRollback(boolean)`, `DalRequestFilter#doFilter`).

Used in: [01-architecture](./01-architecture.md#request-lifecycle)

### Traceable object

A traceable object is an object whose class implements `Traceable`: `Entity#isTraceable` is true when exactly four properties of an entity are [audit properties](#audit-properties), and `Entity#getImplementsStatement` then adds `Traceable` to the interfaces of its [generated class](#generated-class) (`Entity#isTraceable`, `Entity#getImplementsStatement`). `OBInterceptor#doEvent` sets audit values only on a traceable object, through `OBInterceptor#onNew` when any of its four audit properties is null and through `OBInterceptor#onUpdate` otherwise, and then runs `SecurityChecker#checkWriteAccess(Object)`; any other object gets only that write check (`OBInterceptor#doEvent`). `OBInterceptor#onSave` returns true for a traceable object, as it does for an object that implements `ClientEnabled` or `OrganizationEnabled`, and `OBInterceptor#onFlushDirty` does the same when it does not return early (`OBInterceptor#onSave`, `OBInterceptor#onFlushDirty`).

Used in: [04-security-and-filtering](./04-security-and-filtering.md#callbacks)

### Transaction

A transaction is the database transaction of a DAL session: `SessionHandler#begin(String)` begins one when it creates the session of a [pool](#pool), and `SessionHandler#commitAndClose(String)` calls `SessionHandler#flushRemainingChanges` and commits the active transaction only when the pool's stored connection is absent or still open, attempts a rollback instead when a check, the flush or the commit fails or the stored connection throws an `SQLException`, and then closes the connection if it is open and the session (`SessionHandler#begin(String)`, `SessionHandler#commitAndClose(String)`). `SessionHandler#rollback(String)` rolls it back unless the pool's stored connection is already closed, and closes the session unless checking or closing that connection during its cleanup throws an `SQLException`, and `SessionHandler#commitAndStart()` commits and begins a new transaction on the same session (`SessionHandler#rollback(String)`, `SessionHandler#commitAndStart()`). `SessionHandler#setDoRollback(boolean)` records that the transaction is to be rolled back at the end of the thread, and `SecurityChecker#checkWriteAccess(Object, boolean)`, to which `SecurityChecker#checkWriteAccess(Object)` delegates, requests this before it throws for a client or organization failure (`SessionHandler#setDoRollback(boolean)`, `SecurityChecker#checkWriteAccess(Object, boolean)`). Per the `DalRequestFilter` class Javadoc, the transaction of a request ends with the request, committed or rolled back (`DalRequestFilter#doFilter`).

Used in: [01-architecture](./01-architecture.md#reading-guide), [02-runtime-model](./02-runtime-model.md#how-the-runtime-model-is-built), [03-dal-service-api](./03-dal-service-api.md#reading-guide), [04-security-and-filtering](./04-security-and-filtering.md#write-access-check)

### Translatable property

A translatable property is a property whose values can be read in another language from a [translation entity](#translation-entity): `ModelProvider#setTranslatableColumns` looks up the entity of the table named after the column's table plus `_Trl` and passes its property for the same column to `Property#setTranslatable` (`ModelProvider#setTranslatableColumns`). `Property#setTranslatable` makes the property translatable only when the translation entity has an `ad_language` column, the entity has a one-to-many property whose target is the translation entity, and a [parent property](#parent-property) of the translation entity references the entity's first id property; otherwise it logs a warning and `Property#isTranslatable` stays false (`Property#setTranslatable`). With a language, and while `OBContext#hasTranslationInstalled` is true, `BaseOBObject#get(String, Language, String)` looks the [translation record](#translation-record) up at most once per object, through an `OBCriteria` with the client and organization filters off, and returns the value of the [translation property](#translation-property) when one is found (`BaseOBObject#get(String, Language, String)`).

Used in: [02-runtime-model](./02-runtime-model.md#translatable-properties), [04-security-and-filtering](./04-security-and-filtering.md#reads-by-id-and-translation-lookup)

### Translation entity

A translation entity is the entity that holds the translations of a [translatable property](#translatable-property): for each candidate column, `ModelProvider#setTranslatableColumns` looks up the entity of the table named after the column's table plus `_Trl` and passes that entity's property for the same column, the [translation property](#translation-property), to `Property#setTranslatable`, whose Javadoc describes it as the property in the translation table that holds the translation (`ModelProvider#setTranslatableColumns`, `Property#setTranslatable`). `Property#setTranslatable` makes the property translatable only when the translation entity has an `ad_language` column, the property's entity has a one-to-many property whose target is the translation entity, and a [parent property](#parent-property) of the translation entity references the first id property of the property's entity; otherwise it logs a warning and `Property#isTranslatable` stays false (`Property#setTranslatable`). `BaseOBObject#get(String, Language, String)` reads translated values from a [translation record](#translation-record) of the translation entity (`BaseOBObject#get(String, Language, String)`).

Used in: [02-runtime-model](./02-runtime-model.md#translatable-properties)

### Translation parent property

A translation parent property is the [parent property](#parent-property) of a [translation entity](#translation-entity) that references the first id property of a translatable property's entity: `Property#setTranslatable` walks the parent properties of the translation entity and, for the first one whose referenced property is that id property, keeps it as the translation parent property that `Property#getTrlParentProperty` returns, keeps the [translation property](#translation-property) that `Property#getTranslationProperty` returns, and makes the property translatable (`Property#setTranslatable`). When no parent property matches, it logs a warning and keeps neither (`Property#setTranslatable`). `BaseOBObject#get(String, Language, String)` looks for a [translation record](#translation-record) only when an id is passed and the property has a translation parent property, and restricts the lookup to records whose translation parent property references the passed id (`BaseOBObject#get(String, Language, String)`).

Used in: [02-runtime-model](./02-runtime-model.md#dynamic-api)

### Translation property

A translation property is the [property](#property) of a [translation entity](#translation-entity) that holds the translated value of a [translatable property](#translatable-property): for each candidate column, `ModelProvider#setTranslatableColumns` looks up the entity of the table named after the column's table plus `_Trl` and passes that entity's property for the same column, or null when there is no such entity, to `Property#setTranslatable`, whose Javadoc describes it as the property in the translation table that holds the translation (`ModelProvider#setTranslatableColumns`, `Property#setTranslatable`). `Property#setTranslatable` keeps it, as the value that `Property#getTranslationProperty` returns, only when it makes the property translatable, together with the [translation parent property](#translation-parent-property); when the translation property is null, its entity has no `ad_language` column, the property's entity has no one-to-many property whose target is that entity, or no [parent property](#parent-property) of that entity references the first id property of the property's entity, it logs a warning and keeps neither (`Property#setTranslatable`, `Property#getTranslationProperty`). With a language, and while `OBContext#hasTranslationInstalled` is true, `BaseOBObject#get(String, Language, String)` returns for a translatable property the value that the found [translation record](#translation-record) holds for its translation property, and the object's own value when no translation record was found (`BaseOBObject#get(String, Language, String)`).

Used in: [02-runtime-model](./02-runtime-model.md#translatable-properties)

### Translation record

A translation record is an object of a [translation entity](#translation-entity) from which `BaseOBObject#get(String, Language, String)` reads the translated value of a [translatable property](#translatable-property): with a language, and while `OBContext#hasTranslationInstalled` is true, the method looks for it at most once per object, and queries only when an id is passed and the property has a [translation parent property](#translation-parent-property) (`BaseOBObject#get(String, Language, String)`). The query is an `OBCriteria` on the translation entity that matches the passed id through the translation parent property and the passed language, with the client and organization filters switched off and at most one result; a failure is logged and the base value is used, and a call without an id still uses up the one attempt (`BaseOBObject#get(String, Language, String)`). When a translation record was found, the method returns its value for the [translation property](#translation-property) that `Property#getTranslationProperty` returns, and otherwise the object's own value (`BaseOBObject#get(String, Language, String)`).

Used in: [02-runtime-model](./02-runtime-model.md#dynamic-api)

### Typed API

The typed API is the set of getters and setters of the [generated classes](#generated-class), used together with class-based calls such as `OBDal#get(Class, Object)`: `Property#getGetterSetterName` gives the accessor name, dropping the `is` prefix of a boolean property name, and `Property#getTypeName` and `Property#getObjectTypeName` give its type (`Property#getGetterSetterName`, `Property#getTypeName`, `OBDal#get(Class, Object)`). `Entity#getClassName` names the generated class, and the public static `ENTITY_NAME` field that `DalUtil#getEntityName(Class)` reads gives its [entity name](#entity-name) (`Entity#getClassName`, `DalUtil#getEntityName(Class)`). The concrete generated members, and the checks the generated accessors perform, cannot be determined from the repository, because the generated sources are Not Found (`GenerateEntitiesTask#execute`). The alternative is the [dynamic API](#dynamic-api), which needs only the entity name and the runtime model (`BaseOBObject#get(String)`, `Entity#getMappingClass`).

Used in: [01-architecture](./01-architecture.md#entity-generation-generateentities), [02-runtime-model](./02-runtime-model.md#reading-guide)

### Unique constraint

A unique constraint is a database constraint over a set of columns whose combined values must be unique: `ModelProvider#buildUniqueConstraints` reads every unique constraint from the database through a [native query](#native-query) and skips one whose table has no [table-based entity](#table-based-entity) (`ModelProvider#buildUniqueConstraints`). `OBDal#findUniqueConstrainedObjects(BaseOBObject)` takes the unique constraints of the object's entity from `Entity#getUniqueConstraints`, and for each one looks for other objects with the same values, excluding the object's own id when it is not null (`OBDal#findUniqueConstrainedObjects(BaseOBObject)`).

Used in: [02-runtime-model](./02-runtime-model.md#how-the-runtime-model-is-built), [03-dal-service-api](./03-dal-service-api.md#obdalfinduniqueconstrainedobjectsbaseobobject)

### User context

The user context is the `OBContext` of the current thread, which holds the user, [role](#role), client, organization, language and warehouse, and the readable and writable sets computed from them (`OBContext#initialize(String, String, String, String, String, String)`). `OBContext#getOBContext()` returns it, or null when none is set, and `OBContext#setOBContext(OBContext)` stores it in a static thread-local field (`OBContext#getOBContext()`, `OBContext#setOBContext(OBContext)`). `DalRequestFilter#doFilter` attempts to set it for each request by calling `OBContext#setOBContext(HttpServletRequest)`, and logs an error for an `IllegalStateException` from that call without rethrowing it (`DalRequestFilter#doFilter`). That call sets no context when the request has no [HTTP session](#http-session), or when no context is stored in the HTTP session and `OBContext#setFromRequest(HttpServletRequest)` does not return true for a newly created one (`OBContext#setOBContext(HttpServletRequest)`, `OBContext#setFromRequest(HttpServletRequest)`). A newly created context for which that method returns true is stored in the HTTP session and set in the thread, and a stored context is re-initialized from the request when it is out of sync with the HTTP session and then set in the thread, as [04-security-and-filtering.md, Creating and installing a context](./04-security-and-filtering.md#creating-and-installing-a-context) details (`OBContext#setOBContext(HttpServletRequest)`). Module code installs one for known ids with an `OBContext#setOBContext(String, String, String, String)` overload (`OBContext#setOBContext(String, String, String, String)`). `OBContext#createOBContext(String)` creates and initializes a context for a user without setting it in the thread (`OBContext#createOBContext(String)`).

Used in: [01-architecture](./01-architecture.md#layers), [04-security-and-filtering](./04-security-and-filtering.md#reading-guide)

### User level

The user level is the value that `OBContext#setRole(Role)` takes from the role into the user context (`OBContext#setRole(Role)`). `OBContext#setReadableClients(Role)` limits the [readable clients](#readable-clients) to `{"0"}` when it is `S`, and `OBContext#setWritableOrganizations(Role)` adds `"0"` to the [writable organizations](#writable-organizations) when it contains `S` or `C` and removes `"0"` when it is exactly `O` (`OBContext#setReadableClients(Role)`, `OBContext#setWritableOrganizations(Role)`).

Used in: [04-security-and-filtering](./04-security-and-filtering.md#initialization-order)

### User-role assignment

A user-role assignment is a record that links a user to a [role](#role) and has an active flag of its own, separate from that of the role (`OBContext#initialize(String, String, String, String, String, String)`). When no role id is passed and the default role of the user is missing or inactive, `OBContext#initialize(String, String, String, String, String, String)` takes the role of the first active assignment of the user whose role is active, ordered by role id ascending, and throws `OBSecurityException` when there is none (`OBContext#initialize(String, String, String, String, String, String)`).

Used in: [04-security-and-filtering](./04-security-and-filtering.md#initialization-order)

### UUID

A UUID is a universally unique identifier: `DalMappingGenerator#generateStandardID` maps the single id property with type `string` and `unsaved-value="null"`, and adds the generator `DalUUIDGenerator` (boundary) when the id is a UUID id and is not based on another property (`DalMappingGenerator#generateStandardID`). An id based on another property gets a `foreign` generator instead, and any other id gets no generator element (`DalMappingGenerator#generateStandardID`).

Used in: [01-architecture](./01-architecture.md#per-entity-rules)

### View entity

A view entity is an entity whose AD table is flagged as a view: `Entity#initialize(Table)` copies the flag, which `Entity#isView` reads, and makes the entity not mutable (`Entity#initialize(Table)`). `OBDal#save(Object)` logs a warning and returns without saving a `BaseOBObject` of a view entity (`OBDal#save(Object)`). In the mapping, the properties of a view entity get `update="false"` and `insert="false"`, and a [bag](#bag) whose owning or target entity is a view entity is `mutable="false"` and has no cascade (`DalMappingGenerator#generatePrimitiveMapping`, `DalMappingGenerator#generateOneToMany`). `ModelProvider#initialize` does not take the [mandatory flags](#mandatory-flag) of a view entity from the database (`ModelProvider#initialize`).

Used in: [01-architecture](./01-architecture.md#per-entity-rules), [02-runtime-model](./02-runtime-model.md#how-the-runtime-model-is-built), [03-dal-service-api](./03-dal-service-api.md#obdalsaveobject)

### Virtual entity

A virtual entity is the second entity that `ModelProvider#initialize` adds, from the same table, for an entity with [computed columns](#computed-column); its name and class name end in `_ComputedColumns` and its table id ends in `_CC` (`ModelProvider#initialize`, `Entity#initializeComputedColumns`). `Entity#isVirtualEntity` marks it, and `Entity#initializeComputedColumns` makes it not deletable, not mutable and inactive, holding the key columns, the computed columns and the `AD_Client_ID` and `AD_Org_ID` columns; its Javadoc says it is mapped to the same database table as the main entity (`Entity#initializeComputedColumns`, `Entity#isVirtualEntity`). `GenerateEntitiesTask#execute` writes no main class for it and `DalMappingGenerator#generateMapping()` skips it, while for the main entity `DalMappingGenerator#generateComputedColumnsClassMapping` appends a separate class mapping named `<package>.<SimpleClassName>_ComputedColumns` on the same table (`GenerateEntitiesTask#execute`, `DalMappingGenerator#generateMapping()`, `DalMappingGenerator#generateComputedColumnsClassMapping`). The [cross-organization reference check](#cross-organization-reference-check) skips references to a virtual entity (`OBInterceptor#checkReferencedOrganizations`).

Used in: [01-architecture](./01-architecture.md#which-entities-are-mapped), [02-runtime-model](./02-runtime-model.md#how-the-runtime-model-is-built), [04-security-and-filtering](./04-security-and-filtering.md#cross-organization-reference-check)

### Where clause

The where clause is the part of an [HQL](#hql) query that restricts the rows it returns: callers pass it, optionally followed by an [order by clause](#order-by-clause), to `OBDal#createQuery(Class, String)` and its overloads, and `OBQuery#getWhereAndOrderBy()` replaces the upper-case keyword `WHERE`, surrounded by spaces, with `where` because, per its source comment, the upper-case keyword makes Hibernate's HQL parser throw an exception (`OBDal#createQuery(Class, String)`, `OBQuery#getWhereAndOrderBy()`). `OBQuery#createQueryString` takes the part before `order by` as the where clause, strips a leading `where`, and wraps the remaining condition in parentheses after `where`; its source comment gives the reason: the clauses it adds must all be and-ed with the caller's clause (`OBQuery#createQueryString`). `OBQuery#addOrgClientActiveFilter` then adds each client, organization and active restriction that applies, joined to what precedes it with `and`, and writes `where` before the first one when the clause has none (`OBQuery#addOrgClientActiveFilter`). `OBQuery#deleteQuery()` builds its delete statement from the query string from its first `where` onwards and throws `OBException` when there is none (`OBQuery#deleteQuery()`).

Used in: [03-dal-service-api](./03-dal-service-api.md#reading-guide), [04-security-and-filtering](./04-security-and-filtering.md#query-restrictions)

### Writable organizations

The writable organizations are the organization ids to which `SecurityChecker#checkWriteAccess(Object)`, through `SecurityChecker#checkWriteAccess(Object, boolean)`, restricts the organization of an object that the current context writes, apart from three exceptions (`SecurityChecker#checkWriteAccess(Object, boolean)`). `OBContext#setWritableOrganizations(Role)` adds `"0"` when the [user level](#user-level) contains `S` or `C`, adds the [active organizations](#active-organization) of the role, removes `"0"` when the user level is exactly `O`, and then adds every organization registered through `OBContext#addWritableOrganization(String)` (`OBContext#setWritableOrganizations(Role)`). Once the `"0"` branch of `OBContext#setReadableOrganizations(Role)` has stored every organization of the current client in the cached `organizationList` field, and until `OBContext#addWritableOrganization(String)` clears the field, `OBContext#getOrganizationList(Role, List, Set, boolean)` returns a copy of it as those active organizations (`OBContext#getOrganizationList(Role, List, Set, boolean)`, `OBContext#addWritableOrganization(String)`). [04-security-and-filtering.md, Readable and writable sets](./04-security-and-filtering.md#readable-and-writable-sets) records this reuse as an ambiguity that it does not resolve (`OBContext#setWritableOrganizations(Role)`). When the organization resolved by `OBContext#initialize(String, String, String, String, String, String)` is not among the writable organizations, it logs a warning and, if any organization is writable, replaces it with the first element that the iterator of the set returns (`OBContext#initialize(String, String, String, String, String, String)`). `OBContext#getWritableOrganizations()` computes the set when none is cached and returns a copy (`OBContext#getWritableOrganizations()`).

Used in: [04-security-and-filtering](./04-security-and-filtering.md#reading-guide)
